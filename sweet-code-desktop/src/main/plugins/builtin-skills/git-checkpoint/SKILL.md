# 用 git 小步存档

git 就像游戏存档：每做完一件事存一次，改坏了随时能回到上一个存档。「撤销这一轮」只能撤销 AI 最近一轮的改动，git 能回到任何一次存档。

## 先看情况

- 先运行 `git status`，一条命令就能看出：是不是 git 项目、有哪些改动、在哪个分支。
- 不是 git 项目：问用户要不要开启存档功能。同意后运行 `git init`，并检查有没有 `.gitignore`（至少忽略 `node_modules`、`dist`、`.env`）。
- **从不在用户没同意的情况下 push、改远程仓库、或者改 git 配置。**

## 什么时候存档

- 一个任务完成并通过了 `verify-before-done`，就建议存一次。
- 开始一个大改动之前，先把现在能用的版本存下来。
- 存档前用 `git status` 看一眼，确认没有混进 `.env`、密钥、大文件、`node_modules`。

## 怎么存

把这一步合成一条命令，让用户只确认一次：

```bash
git add -A && git commit -m "加上登录表单校验"
```

提交说明：
- 用中文（或者和项目里以前的提交保持一致），一句话说清楚**做了什么**。
- 一次提交只放一件事。两件不相关的事分开提交（`git add 具体文件` 分两次）。

## 回到以前的版本

先说清楚会发生什么，等用户同意后再做：

- 看历史：`git log --oneline -10`
- 只是想看看某个文件以前的样子：`git show <提交号>:路径`，不会改动任何东西。
- 放弃某个文件还没存档的改动：`git restore 路径`。**这会丢掉改动**，执行前要说明。
- 撤销某次已经存档的提交：用 `git revert <提交号>`，它会新建一个反向的提交，历史不会丢。
- 不要用 `git reset --hard`、`git push --force`、`git clean -fd` 这类会永久丢东西的命令，除非用户明确要求并且清楚后果。

## 分支（可选）

用户要试一个不确定的想法时，可以建议开个分支：`git switch -c try-new-layout`。试成功了再合并回来，失败了切回去就行，原来的代码完全不受影响。
