# 项目任务看板（TASKS.md）

对话会被整理、会换新的，但项目文件不会丢。把进度写进 `TASKS.md`，下次打开项目，你和用户都能马上知道做到哪了。

## 什么时候用

- `plan-first` 之后，计划有 3 步以上。
- 用户问「做到哪了」「还剩什么」「下一步呢」。
- 新对话开始时，项目根目录已经有 `TASKS.md`：先读它，再接着做。

## 文件格式

```markdown
# 任务看板

> 目标：一句话说清楚整个项目 / 这一阶段要做成什么样。
> 更新：2026-10-06

## 进行中
- [ ] T3 登录页：表单和校验 —— 改 src/pages/Login.tsx
  - 验证：输入空密码点登录，出现红字提示

## 待办
- [ ] T4 登录接口对接
- [ ] T5 登录后跳转首页

## 已完成
- [x] T1 搭好路由（2026-10-05）
- [x] T2 首页布局（2026-10-06）

## 记一笔
- 决定用 localStorage 存登录状态，以后要换成 cookie。
```

## 拆任务的规矩

- **每个任务半小时内能做完**，做完能单独验证。做不到就再拆。
- 每个任务写上要改的文件和**怎么验证**。
- 按依赖排好顺序：先做别的任务要用到的。
- 编号（T1、T2…）一直往上加，不重复使用，方便用户说「T3 有问题」。

## 怎么维护

- **同一时间「进行中」只有一个任务**。
- 开始一个任务：从待办移到进行中。完成并通过 `verify-before-done`：打勾、移到已完成、写上日期。
- 做的过程中发现新问题：加到待办，不要顺手做掉（除非它挡住了当前任务）。
- 重要的决定、坑、以后要改的地方写进「记一笔」。
- 每次更新 `TASKS.md` 都是一次普通的文件修改（`edit_file`），会经过用户确认。尽量把更新攒到任务完成时一起改，不要每做一小步都改一次。

## 汇报进度

用户问进度时，读 `TASKS.md` 后这样回答：

> 做完了 2/5：T1 路由、T2 首页布局。
> 正在做 T3 登录页表单。
> 下一步是 T4 接登录接口。
