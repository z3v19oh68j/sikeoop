# 改完后自查

像一个严格的同事那样，把刚才的改动再看一遍。目标是在用户发现之前，先发现问题。

## 拿到要看的改动

- 项目用 git：`git diff`（还没暂存的）和 `git diff --staged`。改动很多时先看 `git diff --stat`。
- 没有 git：回顾这一轮你改过的文件，用 `read_file` 重新读一遍改动的地方。
- 用户让你检查他自己写的代码时，先问清楚看哪些文件，或者看 `git diff`。

## 检查清单（按重要程度）

1. **会不会出错**
   - 空值、空数组、`undefined` 有没有处理？
   - 异步：`await` 有没有漏？报错有没有被 catch 住并告诉用户？
   - 改了函数的参数或返回值，所有调用它的地方都跟着改了吗？（用 `search` 查）
   - 边界：0、负数、超长输入、重复点击。
2. **安全**
   - 密码、API Key 有没有写死在代码里，或者会被提交到 git？
   - 用户输入有没有直接拼进 SQL、HTML、命令里？
3. **有没有漏**
   - 需求里的每一点都做了吗？对照 `plan-first` 的计划或 `TASKS.md`。
   - 新加的文件被引用了吗？新的依赖写进 `package.json` 了吗？
4. **多余的东西**
   - 调试用的 `console.log`、注释掉的旧代码、没用到的 import 和变量。
   - 和这次需求无关的改动：应该撤回，或者单独告诉用户。
5. **好不好懂**
   - 名字能看出意思吗？和项目里其他代码的写法一致吗？

## 汇报格式

只说发现的问题，按严重程度排，每条都带位置：

> 自查发现 2 个问题：
> 1. **会出错**：`src/cart.ts:42` 购物车为空时 `items[0].price` 会报错。建议先判断长度。
> 2. **多余**：`src/App.tsx:15` 留了一个调试用的 `console.log`。
>
> 要我把这两个都改掉吗？

没发现问题就说一句「自查过了，没发现问题」，不要硬凑。
