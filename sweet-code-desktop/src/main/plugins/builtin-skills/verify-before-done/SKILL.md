# 完成前先验证

「应该可以了」不算完成。新手不会自己检查，你说好了，他就会相信。**先拿到证据，再说完成。**

## 找到项目的检查命令

先看 `package.json` 的 `scripts`（Python 项目看 `pyproject.toml`、`Makefile`、README），找这几类：

| 检查 | 常见命令 | 能发现 |
|---|---|---|
| 类型检查 | `npm run typecheck`、`npx tsc --noEmit` | 拼错名字、传错参数 |
| 代码检查 | `npm run lint` | 明显的错误写法 |
| 测试 | `npm test`、`npx vitest run`、`pytest` | 逻辑错误 |
| 构建 | `npm run build` | 打包时才会出的错 |

只用项目里已经有的命令，不要为了验证去装新工具。

## 验证的顺序

1. 先跑最快、和改动最相关的：只跑改到的那个测试文件，或者类型检查。
2. 都过了，再跑一次完整的检查（全部测试或构建）。命令能用 `&&` 连起来就连起来，比如 `npm run typecheck && npm test`，让用户少确认几次。
3. **看完整输出**：退出码是不是 0？有没有 error？有没有新的 warning？

## 结果怎么说

- **通过了**：说清楚跑了什么、结果是什么。
  > 跑了 `npm run typecheck` 和 `npm test`，12 个测试全部通过。
- **失败了**：如实说，贴出关键的报错，然后用 `debug-systematically` 去修。不要说「基本可以了」「应该没问题」。
- **没法自动验证**（界面、样式、需要开服务器、需要真实账号）：给用户一个具体的检查清单：
  > 1. 在终端运行 `npm run dev`（点代码块上的「在终端运行」）
  > 2. 打开 http://localhost:5173 ，点右上角的「登录」
  > 3. 应该看到一个粉色的弹窗；如果没有，点终端的「帮我看看」发给我

## 不要做的事

- 没跑过就说「测试通过」。
- 只跑了一部分，却说「全部没问题」。
- 为了让检查通过去删测试、加 `// @ts-ignore`、把报错吞掉。真遇到这种情况，先问用户。
- 用 `run_command` 跑 `npm run dev` 这种不会结束的命令来「验证」。
