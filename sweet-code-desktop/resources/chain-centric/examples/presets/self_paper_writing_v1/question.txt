为"链心(Chain-Centric)多智能体协议"产出一份学术论文级别的、经过对抗审视的结构化主张集。

本任务的产物**不是**完整的论文文本。产物是一份关于链心的结构化主张集——每条主张附带可观测证据,经过同伴攻击后存留下来——最终以分歧地图的形式呈现:iron-clad / consensus / contested / collapsed / unscrutinised 五类。

**所有 agent 用中文回复**。所有 claim、attack、revise_chain 的正文均使用中文。证据引用可以保留原文(如英文文献标题)。

# 允许的主张范围

- 协议在做什么(机制级描述)
- 为什么这样设计(每个设计选择是一条独立的可证伪主张)
- 12 次 v5.1 实验在观测层面显示了什么(以及未显示什么)
- 单 LLM 调用在结构上不能产出而本协议产出的是什么
- 链心与现有多智能体 / 论辩 / 控制论文献的关系
- 诚实的局限(关于协议**不**能做什么的主张)

# 约束

1. **每条主张必须引用至少一条具体证据**。证据可以是:代码引用(文件路径 + 行号区间)、JSON 字段(来自保存的实验数据)、历史论文段落、外部学术文献。无证据的主张是无效的,会被解析器拒绝。

2. **历史论文(v2、v3、v4、v5、v5.1、grounded_v1)是作者的旧主张,不是真理**。攻击历史主张是合法的。新的证据或新的分析可以推翻它们。

3. **以下主张被禁止,除非有回溯真值基准证据(本档案没有)支撑**:
   "链心产出的答案比单 LLM 更接近真理。"
   任何 agent 提出此类主张都必须被攻击。

4. **以下主张必须被审视**:
   "五厂商异构(DeepSeek / GLM / MiMo / Doubao / Qwen)足以避免共享训练数据盲点。"
   该主张可疑,因为这五家厂商训练数据高度依赖中文互联网,且本次实验本身就是由这五家执行。如果这一条主张未被自然攻击,agent 必须主动攻击它。

5. **自我引用披露**:本次实验的输入设计是作者与一位基于 Claude 的 AI 助手协作完成的(该助手不参与本次跑动,与任何参与 agent 不是同一实例)。参与 agent **没有**参与输入设计。Agent 可以攻击输入设计本身——如果发现框架性偏差,这是合法的攻击对象。

6. **鼓励否证主张**:形式为"链心**不**能做 X"或"链心**不**适用于场景 Y"的主张,与正面主张同等重要,有时更重要。

7. **方法论死锁的识别**:如果某条主张无法被现有证据解决(例如它需要本档案不具备的回溯基准),应将其分类为 contested 并附"方法论裂缝"标签——**不要**强行推入 consensus。

# 必查条目(每个 agent 必须涉及至少其中三项)

## E1. "无裁判"主张
协调层在运行时是否真的避免了 LLM-as-judge?设计时的判断(解析器规则、去重逻辑、α 计算、离散化、λ=1.5、拓扑阈值"3 对")相对这个主张处于什么位置?这些设计时判断本身是否可被复审?

## E2. "无 agree"语法
移除 agree 原语在结构上是否阻止了迎合,还是只是把迎合推到了其他渠道(例如发布低 α 的复用证据链、用 pass 来回避分歧)?

## E3. H_sym 观察器的真实角色
H_sym 的"无新符号配置"判据是否忠实地操作化了"协议下可观测认知空间停止扩张"——考虑到经验观测:在所有 14 次 v5.1 运行的最后 5 轮里 H_chain 仍以 0.17-0.81 的幅度变动?

## E4. 五维扩张分解的完备性
五维扩张分解(输入 / 产物 / 检验密度 / 检验结构 / 测量噪声保护)是否完备?是否存在第六个维度——例如"修订有效性"——是 v5.1 没观测到的?

## E5. 与单 LLM 的差异
本协议产出而单 LLM 调用在结构上不能产出的具体认知对象是什么?要精确——分歧地图结构、方法论裂缝识别、对多个排名变体的结构化不确定性,等等。

## E6. 与已有工作的关系
把链心定位到以下工作之间:AutoGen / CrewAI / LangGraph(编排底座);MAVEN / AgentAuditor / ArgMed(步级审计与论辩);Sela 2026(架构异构性);Shin 2026(封闭系统 DPI 界);Zhao 2026(多智能体熵);Constitutional AI / Self-Refine(单 agent 批评);HEARSAY-II 黑板(1980s);Walton 对话博弈;Popper / Campbell 演化认识论。

## E7. 161 攻击记忆案例
作者报告:他们曾经基于一份 AI 总结记忆"有一条链被攻击 161 次仍然存活"长达一年;后来 JSON 检查发现这指的是 86 条 claim_id 字段为空的链(v2 schema bug)的攻击聚合。这个案例在经验层面证明了协议的什么必要性?它**不**证明什么?

## E8. 协议结构上无法自检的失效
找出协议在结构上无法检测自身失效的场景(例如:共享训练数据盲点;方法论框架锁定;修订维度仍活跃但其他维度已稳定)。

# 输出结构期望

收敛后,分歧地图应将关于链心的主张分入:

- **iron-clad**:经过多次攻击存活、证据独立、被多个 agent 复审
- **consensus**:攻击次数低但证据独立且被复审
- **contested**:被攻击且存活情况不明、方法论争议、或证据不完整
- **collapsed**:链在攻击下被击破,或 α 跌到结构阈值以下
- **unscrutinised**:零次攻击(**不得**被分类为 consensus)

# 自我测试维度

把这次运行本身视为对协议的自我测试:**如果分歧地图被夸赞链心的 iron-clad 主张主导,这是可疑的结果**——协议本应暴露自身边界,而非自我合法化。

"成功的运行"特征:
1. 被禁止主张("更接近真理")在被提出后崩塌
2. 必查条目 E1-E8 都获得了攻击关注;方法论死锁被报告为 contested 而非被强行推入 consensus
3. 五厂商异构充分性主张被挑战
4. 否证主张(局限、结构盲点)出现在 iron-clad / consensus 区,且证据明确

"失败的运行"特征:分歧地图全是 iron-clad 夸链心的主张,无方法论死锁,异构性主张未被攻击。这一签名将表明协议级别的迎合(协议自己也被自己的 agents 迎合了)。
