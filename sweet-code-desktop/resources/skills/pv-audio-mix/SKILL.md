# 宣传片混音

输入：无声视频、同一份时间表（`timeline.json`，由画面页导出）、旁白 WAV、配乐、音效文件、`CREDITS.md`。全部路径限定在当前 PV 项目内，输出使用新文件名。

## 1. 时间表
只读时间表里的场景旁白起点和音效点（秒）。旁白在 `scene.vo` 处开始，音效在 `cue.t` 处开始，不在音频脚本里另抄数字。

## 2. 旁白处理链
按顺序：重采样到 48 kHz、立体声 → 90 Hz 高通去低频 → 轻压缩（比例约 2.5:1）→ 提音量 1.2–1.5 倍 → 按时间点延迟 → 尾部补静音，保证每句长度一致。

## 3. 配乐
- 先用节拍脚本估出速度和起拍偏移，结果是粗算，必须人耳复核。
- 裁掉前奏偏移，让拍点网格从 0 秒开始；每个切点都应落在整小节的第一拍上。
- 配乐音量压到四成左右，开头淡入约 0.3 秒，片尾淡出约 4 秒。
- 用旁白做侧链压缩（`sidechaincompress`），说话时配乐自动让开。侧链输入是旁白的副本，不是混好的总线。

## 4. 音效
每个音效单独处理：裁到需要的长度（超长的循环音如打字声只取前几秒），末尾做短淡出，按时间点延迟，音量约为旁白的一半。

## 5. 合成顺序
1. 旁白、音效各自用 `amix` 合成一路（`normalize=0`，避免被自动拉平）。
2. 配乐经侧链后与旁白、音效合并（`amix`，`normalize=0`）。
3. 整体做响度标准化：`loudnorm=I=-14:TP=-1.5:LRA=11`。
4. 输出 AAC 192 kbps，视频流直接复制，`-movflags +faststart`，时长以时间表总长为准。

## 6. 命令参数（数组形式，不拼 shell）
```js
import { execFileSync } from "node:child_process";
execFileSync("ffmpeg", ["-y", "-loglevel", "error",
  "-i", videoPath, "-i", musicPath, "-i", voicePath,
  "-filter_complex", filterGraph,        // 由脚本按时间表逐条拼接，片段之间用分号
  "-map", "0:v", "-map", "[aout]",
  "-c:v", "copy", "-c:a", "aac", "-b:a", "192k",
  "-movflags", "+faststart", "-t", String(total), outPath]);
```
路径全部用绝对路径，作为数组元素传入。不要把用户输入拼进滤镜字符串；滤镜里的文件路径如需出现，要先转义。

## 7. 编码器
只用项目已确认可用的编码器和构建。不要为了某个编码器悄悄换成依赖 GPL 组件的构建，也不要写依赖 GPL 组件的配方。

## 8. 素材与许可（CREDITS）
每个外来文件记一行：文件名、名称、作者（不明写“页面未列作者”）、来源页面、直链、许可名称、下载日期。许可条款原文没读到，就写“待人工确认”。只下载媒体文件，不下载也不运行脚本和程序。素材放进项目的 `downloads/`，不自动联网拉取新的音乐。

## 9. 密钥
配音或其他服务的密钥只从项目内的本地文件读取，读后只在请求头里使用。不打印、不写进时间表、混音脚本、日志或汇报。

## 10. 自查
- 用关键时间点（每个旁白起点前后、切点、片尾）对听一遍，确认没有错位和爆音。
- 量一次整体响度，记录数值。
- 汇报里写清检查了哪些时间点；没有人听过的，照实写“未人工听过”。
