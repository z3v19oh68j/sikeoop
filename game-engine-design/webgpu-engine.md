# 鲸渲 jingxuan：渲染层设计稿

> **状态（2026-10-10）**：保留为鲸渲特效库（套件 G3 阶段，可选）的设计稿，总方案见 `sikeoop-game-kit.md`。


> 本文是鲸渲引擎的**渲染层**。整体方案（运行时、可视化编辑器、阶段划分）见 `jingxuan-engine.md`。

> 状态：设计稿，未开工。日期：2026-10-10。名字已定：鲸渲（代码标识 `jingxuan`）。定位和方向见 `jingxuan-positioning.md`。

## 1. 要解决什么

- 给 sikeoop 的「网页游戏」路线做一个自己的渲染底座。底座要满足三点：
  - 只走 WebGPU；
  - 粒子全部在 GPU 上算；
  - 效果靠 shader 写出来。
- 它不是另一个 Three.js。它的差异在**对 AI 友好**：
  - 每一帧做了什么、花了多长时间，都能导出成一份 JSON，AI 在内置浏览器里直接读；
  - shader 写错时，报错能定位到哪一行，并且有中文说明；
  - 有「确定性模式」，固定步长和随机种子，同一段输入每次都渲染出同一张图，所以能用截图做回归测试。
- 第一批目标：
  - 2D 和 2.5D 的动作、弹幕、休闲游戏；
  - 屏幕上同时跑 **100 万个粒子**，在 M4 基础款上保持 60 帧（开发初期只针对 macOS M4 以上芯片，见 `jingxuan-positioning.md` 第 2.5 节）；
  - 有一套常用的 shader 特效。

## 2. 已经定下的选择（理由）

| 选择 | 理由 |
|---|---|
| **只做 WebGPU，不做 WebGL 兼容** | 粒子靠计算着色器、间接绘制和存储缓冲，WebGL 做不了，硬做兼容会把架构拖垮。Chrome、Edge、sikeoop 自己（Electron 44）、Safari 26 和 Windows 上的 Firefox 都能跑 WebGPU。不支持的浏览器给一个清楚的提示页 |
| **TypeScript + WGSL** | 和 sikeoop 是同一套技术，AI 写起来也最顺手 |
| **不依赖第三方渲染库** | 管线、资源、粒子全部自己掌握，才谈得上性能和「对 AI 友好」。数学部分只依赖 `wgpu-matrix`（MIT 协议，很小） |
| **先 2D，再 3D** | 2D 能最快做出能玩的游戏，粒子和后期也最能出效果；3D（glTF、阴影）放到 P3 |
| **渲染图（frame graph）驱动** | 每个 pass 声明自己读什么、写什么，由引擎排顺序、复用临时纹理。后期链和粒子都挂在渲染图上，也方便把每一帧导出成 JSON 给 AI 看 |

## 3. 总体结构

```
游戏代码 / AI 写的代码
        │
┌───────▼────────────────────────────────────────────────┐
│ 场景层   Camera · Sprite/Mesh 实例 · Material · Emitter │
├────────────────────────────────────────────────────────┤

│   ├ 粒子：emit → simulate → (sort) → draw（全部 GPU）   │
│   ├ 主绘制：实例化批量绘制（2D 精灵 / 网格）            │
│   └ 后期：HDR → Bloom → 色调映射 → LUT → FXAA           │
├────────────────────────────────────────────────────────┤
│ Shader 系统  WGSL 模块拼装 · 宏开关 · 热重载 · 报错定位 │
├────────────────────────────────────────────────────────┤
│ 资源层   缓冲（环形 uniform）· 纹理 · 采样器 ·          │
│          BindGroup 缓存 · Pipeline 缓存（按状态哈希）   │
├────────────────────────────────────────────────────────┤
│ 设备层   Adapter/Device · 设备丢失恢复 · 画布/DPR/缩放  │
├────────────────────────────────────────────────────────┤
│ 工具     GPU 计时（timestamp-query）· 统计浮层 ·        │
│          inspect() JSON · 确定性模式 · 调试视图         │
└────────────────────────────────────────────────────────┘
```

## 4. 各层要点

### 4.1 设备层
- 目标是 Apple 芯片的集成 GPU，`powerPreference` 不影响选哪块 GPU，照常设为 `"high-performance"`。可选特性按需开：`timestamp-query`、`shader-f16`、`float32-filterable`，没有也照常能跑。
- **设备丢失后自动重建**：资源和 pipeline 都按描述重新生成，游戏代码无感知。
- 画布按 DPR 设置分辨率，并有最大像素上限，防止 4K 屏把显存吃满。支持动态分辨率：掉帧时自动降一档。

### 4.2 资源层
- **uniform 环形缓冲**：每帧申请一大块，用动态偏移分给各个绘制调用，避免每次绘制都新建 buffer。
- **按状态哈希缓存 pipeline**：哈希的内容包括 shader、宏开关、混合模式、深度格式和目标格式。首次编译走异步 `createRenderPipelineAsync`，期间不卡帧。
- BindGroup 按「布局 + 资源」缓存；资源换掉时，相关 BindGroup 自动失效。
- 纹理加载：图片解码放在 `createImageBitmap` 里，不卡主线程；mipmap 用 compute 生成。

### 4.3 Shader 系统
- WGSL 按模块拼装：`#include "noise.wgsl"`、`#define SOFT_PARTICLES`，再生成不同的变体。
- **热重载**：开发模式下改了 `.wgsl` 文件，只重新编译受影响的 pipeline，画面不刷新、状态不丢。
- **报错定位**：用 `getCompilationInfo()` 拿到错误，映射回拼装前的「哪个文件第几行」，画面上弹出浮层，同时写进 `inspect()`，AI 可以直接读到。
- 内置 shader 库：
  - 噪声：value、simplex、curl；
  - 色彩：sRGB 和线性色互转、ACES 和 AgX 色调映射；
  - SDF 形状；
  - 常用特效：溶解、描边、扭曲、受击闪白、水面波纹、扫光、像素化。

### 4.4 渲染图
- 每个 pass 写成 `addPass(name, { reads, writes, execute })`，可以是 compute 或 render。
- 编译渲染图时：
  - 剔除没人读的 pass；
  - 排出执行顺序；
  - 生命周期不重叠的临时纹理共用同一块显存。
- 每个 pass 都带 GPU 计时和 debug label，用浏览器的 GPU 调试工具看时一目了然。

### 4.5 GPU 粒子（P1 的核心）
- **数据**：按属性分开存在存储缓冲里（结构数组，SoA）：位置、速度、颜色、大小、寿命、种子。容量上限可以配，默认 100 万。
- **活粒子和死粒子两个列表**，配原子计数器：
  1. `emit`（compute）：从死列表取出槽位，初始化新粒子。发射形状有点、圆、矩形、网格表面和贴图采样。
  2. `simulate`（compute）：
     - 受力：重力、阻力、curl 噪声、吸引和排斥点、涡旋；
     - 颜色和大小随寿命变化，变化曲线烘成 1D 纹理；
     - 和深度缓冲碰撞反弹；
     - 寿命到了的粒子放回死列表。
  3. `compact`：生成间接绘制参数，CPU 不读回任何数据。
  4. `draw`：`drawIndirect` 加顶点拉取（vertex pulling）画出 billboard。混合模式：
     - 叠加和预乘 alpha 不用排序；
     - 普通 alpha 混合用 GPU 双调排序（bitonic）。
- **效果**：软粒子（按深度渐隐）、序列帧动画、拖尾（P2，环形历史缓冲）。
- 一个 workgroup 64 线程（Apple GPU 的 SIMD 宽度是 32，正好两组），100 万个粒子需要 15625 个 workgroup，在 WebGPU 默认上限（65535）之内；存储缓冲约 64MB，在默认上限 128MB 之内。

### 4.6 主绘制（2D）
- 精灵全部走实例化绘制：一个图集加一个材质就是一个批次。图集打包工具放在构建期。
- 2D 灯光（P2）：法线贴图加点光源，延迟累加到光照缓冲。

### 4.7 后期（P2）
- 场景先画到 `rgba16float` 的 HDR 缓冲。
- 后期链：
  - Bloom：双重滤波，先降采样再升采样；
  - 色调映射：ACES 或 AgX；
  - 色彩分级：3D LUT（`.cube`）；
  - 抗锯齿：FXAA，以后再加 TAA。
- 每一步都能开关，参数能实时调。

### 4.8 对 AI 友好的部分（sikeoop 的差异点）
- **`engine.inspect()` 返回 JSON**，内容包括：
  - 每个 pass 的耗时；
  - 绘制调用数、粒子活跃数；
  - 显存估算；
  - shader 编译错误；
  - 设备丢失次数。
  - sikeoop 内置浏览器的 `browser_console` / `browser_snapshot` 可以直接读到。
- **确定性模式**：`engine.deterministic({ seed, fps: 60 })` 固定步长，随机数由种子决定，同样的输入每次渲染出同一张图，可以截图做回归测试，接上 sikeoop 的「测试与回归」。
- **输入回放**：录下键盘和鼠标操作，再原样重放，AI 能一遍遍复现同一个 bug。
- **调试视图**：一键切换显示深度、粒子密度、过度绘制（overdraw）和各 pass 的输出。

## 5. 仓库结构

```
jingxuan/
├─ packages/
│  ├─ core/        设备、资源、shader 系统、渲染图、场景、统计
│  ├─ particles/   GPU 粒子
│  ├─ post/        后期链
│  ├─ shaders/     内置 WGSL 库
│  ├─ three/       互通包：Three.js（共用 GPUDevice，见定位文档第 8.5 节）
│  └─ pixi/        互通包：PixiJS v8
├─ examples/       每个功能一个可运行示例（也是验收场景）
├─ bench/          性能基准场景
└─ docs/           API 文档，以及给 AI 读的使用说明（AGENT.md）
```

- 用 Vite 做开发服务器和打包；CPU 部分（渲染图排序、哈希、曲线烘焙）用 vitest 测。
- GPU 部分的验收：在 sikeoop 内置浏览器里跑示例，开确定性模式截图比对，同时读 `inspect()` 看性能。

## 6. 分阶段

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P0 底座**（约 1 周） | 设备层、资源层、shader 系统（含热重载和报错定位）、最小渲染图、实例化精灵、统计浮层、`inspect()` | 1 万个精灵稳定 60 帧；故意写错 shader，能准确报出出错的文件和行；设备丢失后能自动恢复 |
| **P1 GPU 粒子**（约 1 周） | emit / simulate / compact / drawIndirect、各种力场、curl 噪声、深度碰撞、软粒子、发射器 API | M4 基础款上 100 万粒子保持 60 帧；CPU 每帧不读回任何数据 |
| **P2 特效和后期** | HDR、Bloom、色调映射、LUT、FXAA；shader 特效库；2D 灯光；粒子拖尾和排序 | 每个特效一个示例；后期整条链在 1080p 下不超过 2ms |
| **P3 3D** | glTF 网格、简化版 PBR、方向光阴影、GPU 视锥剔除 | 载入一个标准 glTF 场景，并有阴影 |
| **P4 接进 sikeoop** | 「WebGPU 游戏」项目模板、给 AI 的使用说明（技能）、截图回归接入「测试与回归」、内置浏览器里显示性能面板 | 一句话让 sikeoop 生成一个带粒子特效的小游戏，AI 自己试玩、截图、修 bug |

## 7. 风险

- **兼容性**：手机浏览器（尤其 iOS Safari）对 WebGPU 的支持和各种上限都在变；P0 先只承诺桌面浏览器。
- **平台范围**：开发初期只在 macOS M4 以上芯片上设计和调优（Chrome / Edge / Safari 26 / sikeoop 内置浏览器），其他平台以后作为单独阶段来做。
- **工作量**：P0–P2 是能做游戏的最小集，P3 的 3D 工作量会翻倍，要看到时候的需求再定。
