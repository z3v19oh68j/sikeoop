## 1. 一句话定位

**鲸渲是一个在浏览器里打开就能做游戏的引擎和编辑器。**
- 人用拖拽和「事件表」做游戏，AI 用同一套命令改同一个项目，两边看到、改到的是同一份东西。
- 做完一键发布成网页，别人点开链接就能玩。

## 2. 和市面上的区别

| 已有的 | 问题 | 鲸渲 |
|---|---|---|
| Construct 3、GDevelop（网页里可视化做游戏） | 前者闭源收费；后者渲染基于 PixiJS 加 WebGL，做不了 GPU 粒子和计算着色器级别的特效；都不是为 AI 设计的 | 开源；渲染原生 WebGPU，百万粒子和 shader 特效是本职 |
| PlayCanvas 编辑器（网页里的 3D 编辑器） | 编辑器是商业服务，项目放在它的云上 | 项目就是你硬盘上的一个文件夹，文本格式，能放进 git 版本管理 |
| Godot、Cocos、Unity（桌面编辑器 + 网页导出） | 要装大编辑器；网页只是导出的一个平台，体积大、启动慢 | 网页是主平台；编辑器本身就是网页，也能直接在 sikeoop 里打开 |
| 所有现有引擎 | AI 只能改代码，看不到场景，也碰不到编辑器 | **编辑器里的每一个操作都是一条命令**，人点按钮和 AI 调用走的是同一条路；场景是带格式说明（schema）的文本，AI 能直接读、直接改；试玩时有 `inspect()`，还能用固定输入复现 |

## 4. 可视化编程：怎么「写」游戏逻辑

三种写法，跑在同一个运行时上，可以混着用：

| 写法 | 给谁 | 适合写什么 |
|---|---|---|
| **事件表**（主力） | 新手，以及大多数游戏逻辑 | 「条件 → 动作」一行一行写，比如「当 玩家 碰到 金币 → 金币 消失，分数 +1，播放 叮」。比积木（Scratch）紧凑，比节点图好读；Construct 和 GDevelop 已经证明这种写法能做出完整的游戏 |
| **节点图** | 美术、技术美术 | 粒子发射器、shader 特效、动画状态机。这些本来就是「数据流」，用连线表达最直观 |
| **TypeScript 组件** | 程序员和 AI | 复杂算法、寻路、程序化生成。写好的组件会在事件表里变成可选的条件和动作 |

- **事件表和节点图都存成 JSON**，运行时直接解释执行；发布时编译成 JS，跑得更快。
- **每张事件表都能「查看等价代码」**，生成只读的 TypeScript，方便人学习，也方便 AI 理解。
- 条件和动作的清单是**可以扩展的**：每个组件都可以声明「我提供哪些条件和动作」，事件表里就能选到它们。
- 全部中文：条件、动作、参数名都有中文名称，也支持拼音搜索，和 sikeoop 命令面板的做法一样。

## 5. 项目格式（人和 AI 都能直接读写）

```
my-game/
├─ jingxuan.json          项目设置：名字、分辨率、物理、输入映射
├─ scenes/level1.scene.json
├─ prefabs/enemy.prefab.json
├─ logic/player.events.json      事件表
├─ graphs/explosion.particle.json 节点图（粒子）
├─ scripts/pathfind.ts           TypeScript 组件
└─ assets/                       图片、声音、字体；另有 assets.json 记录导入设置
```

- 每种文件都有 JSON Schema。编辑器和 AI 写入前先校验，格式不对就拒绝，并告诉对方哪里错了。
- 引用一律用稳定 id，不用文件路径，所以改名、挪位置都不会断。
- 按「一个对象一行、键名排序」的方式写出文件，git 对比时改动清楚，多人也能合并。

## 6. 编辑器

- **技术**：React + TypeScript，和 sikeoop 是同一套，以后能直接嵌进 sikeoop；场景视图由鲸渲自己渲染。
- **面板**：
  - 场景视图：移动、旋转、缩放手柄，网格吸附，2D / 2.5D 相机；
  - 层级树；
  - 属性面板：按 schema 自动生成，改了马上看到效果；
  - 资源库：拖进去就能导入，自动打图集、压缩声音；
  - 事件表编辑器；
  - 节点图编辑器：粒子和 shader 改完立刻预览；
  - **试玩模式**：在编辑器里直接玩。停下以后场景恢复原样；也可以选择「把试玩中的改动保留下来」；
  - 控制台：显示 `inspect()` 和报错。
- **命令系统**（核心）：
  - 编辑器里的每个操作都是一条命令，比如 `entity.create`、`component.set`、`event.addRow`；
  - 命令可以撤销和重做，可以录下来回放；
  - 对外开放成 MCP 服务器，sikeoop 的 AI 用的就是这套命令；
  - AI 和人都能直接改项目的 JSON 文件，编辑器发现文件变了就自动重新加载。
- **文件读写**：
  - 在 sikeoop 里：通过 sikeoop 的文件接口；
  - 在 Chrome / Edge 里：用浏览器的文件系统 API，直接打开本地文件夹；
  - Safari 没有打开本地文件夹的能力：只能用浏览器自己的存储，再导入导出 zip。

## 7. 运行时

| 模块 | 做法 |
|---|---|
| ECS | 自己写，小而快：组件存在类型化数组里（SoA）；场景树就是一个父子关系组件 |
| 渲染 | 渲染层：精灵、瓦片地图、GPU 粒子、shader 特效、后期 |
| 物理 | Rapier（WASM，MIT / Apache）。先做 2D，3D 放在 P5 |
| 声音 | Web Audio，支持空间音效；配一个简单混音器 |
| 输入 | 键盘、鼠标、手柄、触摸，用「动作映射」把按键和动作分开 |
| 动画 | 序列帧、补间、动画状态机（节点图）；Spine 运行时以后再做 |
| 游戏内 UI | 自带一套简单 UI：文字、按钮、进度条，用九宫格图片做底 |
| 资源 | 按需加载、引用计数、预加载列表；发布时生成图集、压缩声音 |
| 确定性 | 固定步长、随机数由种子决定、操作可以回放；沿用渲染层的设计 |

## 8. 发布

- **一键导出静态网页**：一个文件夹或 zip，只包含运行时和游戏资源。
- **一键发布到 sikeoop 的服务器**：在你的服务器上拿到一个可以分享的链接，比如 `play.sikeoop.modgert.online/xxx`。
- **小游戏平台**（微信、抖音）目前只支持 WebGL，鲸渲走 WebGPU，**这一阶段不做**。

## 9. 和 sikeoop 怎么配合

- sikeoop 里可以直接打开鲸渲编辑器，作为一个标签页，和代码编辑器、内置浏览器并列。
- AI 拿到的是鲸渲的命令（MCP），能做的事包括：
  - 搭场景、写事件表、调粒子；
  - 进入试玩模式、截图、读 `inspect()`。
  - 做完以后用固定输入回放验证，再接进「测试与回归」。
- 用户说一句「做一个躲避弹幕的小游戏，爆炸要炫」，AI 就能用鲸渲的命令搭出来；人随后在可视化编辑器里接着调。

## 10. 分阶段（重新排）

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P0 渲染底座** | 同设计稿 P0：设备、资源、shader、渲染图、精灵、`inspect()` | 1 万个精灵稳定 60 帧；shader 报错能定位到哪一行 |
| **P1 运行时核心 + GPU 粒子** | ECS、场景格式和 schema、输入、资源加载、Rapier 2D、声音；百万粒子 | 用纯 JSON 场景加 TS 组件跑通一个能玩的小游戏；M4 上 100 万粒子保持 60 帧 |
| **P2 编辑器骨架** | 命令系统（撤销、录制）、场景视图和手柄、层级、属性面板、资源库、试玩模式、文件读写 | 不写代码，在编辑器里搭出一个场景并试玩 |
| **P3 可视化编程** | 事件表编辑器和执行器、粒子和 shader 的节点图、「查看等价代码」 | 只用事件表做出一个完整的小游戏（比如打砖块）；用节点图做出一个爆炸特效 |
| **P4 AI 与发布** | 命令开放成 MCP、接进 sikeoop、项目模板、导出、一键发布、确定性回归 | 一句话让 AI 在鲸渲里做出可玩的小游戏，并发布出一个链接 |
| **P5 3D** | glTF、简化版 PBR、阴影、Rapier 3D | 看需求再定 |

- **工作量要说实话**：P0–P4 是一个完整产品，按一个人加 AI 军团估算，**大约要 2–3 个月**。P2 编辑器和 P3 事件表最花时间。每个阶段都单独交付、单独可用，不用等到最后才能用。

## 11. 不做什么（替换定位文档第 5 节）

- 不做 WebGL 兼容；暂时不支持小游戏平台。
- 不做 3A 级 3D，不追求写实画质。
- 不做云端项目托管和多人实时协作，项目就是本地文件夹加 git。实时协作以后再看。
- 不自己写物理引擎（用 Rapier），不做网络联机（推荐 Colyseus）。
- 不兼容 Unity、Godot 的项目格式。
- **原来的「不做可视化编辑器」作废**：编辑器现在是核心。

## 12. 需要你决定的事

1. **名字**：引擎和编辑器统一叫「鲸渲」，还是编辑器另起一个名字（比如「鲸渲工坊」）？
2. **开源协议**：建议 MIT。
3. **代码放在哪**：建议在根目录建 `jingxuan/`，用 monorepo 管理：`packages/render`、`runtime`、`editor`、`schema` 等。
4. **第一个目标游戏**：拿什么当整条线路的验收，比如「弹幕射击」，还是「打砖块 + 炫酷粒子」？
5. **先做哪一步**：按顺序从 P0 渲染底座开始。如果你想先看到编辑器长什么样，也可以先做 P2 的界面原型，再回头接运行时。
