方案：`docs/方案-跨agent打洞.md`（含第 11 节第零批实测结果）。路径相对 `sweet-code-desktop/`。

> 这是草稿，交给指挥官定稿后再派。第零批已确认：opencode 走 ACP 可行，插件在 ACP 下可省，权限走 `session/request_permission`，取消用 `session/cancel` 且及时。

## 0. 目标

让 sikeoop 能把一个任务交给**外部 agent**（第一个对象：本机 opencode），通过 ACP（Agent Client Protocol，JSON-RPC over stdio）对话，全程是调度核心里的一个任务：可排队、出进度、要权限时上审批卡、可取消、结束给回执（含 sikeoop 自己量出来的改动文件清单）。

**本批只做出站（sikeoop → opencode）一个方向、一个对象。** 入站四个工具、交接包、更多对象、外部配对都在后面几批。

## 1. 约束

- 只在开发版显示（`SHOW_UNFINISHED`）。
- `shared/types.ts`、`preload` 只新增；不改审批流程既有逻辑、模型路由、深度科研、发布、CLI 扩展既有行为、更新卡片、额度续写。
- 不打包 opencode，不改它的全局配置，不全局装插件：设置只通过 `OPENCODE_CONFIG_CONTENT` 等环境变量对单次进程生效（沿用 `cli-agents/bundled.ts` 的做法）。
- 不启动应用、不 git 提交。新逻辑配单元测试（协议握手、进度解析、权限往返、取消、异常，用一个假的 ACP agent 脚本，不真连 opencode）。
- `npm run typecheck` 0 新增错误；`npm test` 全过。

## 2. 要做的

### 2.1 新执行体 `agent`（调度核心）

- `DispatchExecutorKind` 增加 `"agent"`（上次加 `"process"` 的改法）。调度台标签「外部 agent」。
- 新建 `src/main/dispatch/agent.ts`：`AgentExecutor implements Executor`。`kind="agent"`，`ref` 用会话标识，`run(job, signal)` 把任务交给连接器，解析进度，遇权限回调审批，`signal` 触发时发协议取消。`ready()`/`alive()` 由连接器状态决定。
- 不复用 `cli` / `process`（理由见方案第 6 节）。

### 2.2 ACP 连接器

- 新建 `src/main/connectors/acp.ts`：启动 `opencode acp` 子进程，按 JSON-RPC 2.0 over stdio 收发。实现：
  - `initialize`（带 `clientCapabilities`）、`session/new`（返回 `sessionId`）。
  - `session/prompt` 发任务，收 `session/update` 流（`agent_message_chunk` / `tool_call` / `tool_call_update`），以响应里的 `stopReason` 结束。
  - 收到 `session/request_permission` 请求 → 转成审批卡 → 把用户选的 `optionId` 原样回 `{outcome:{outcome:"selected", optionId}}`（选项照原样透传，别自己翻译）。
  - `session/cancel` 通知做取消。
  - 子进程崩溃 / stdio 断开 → 任务判失败。
- 纯协议部分（把一行 JSON 解析成进度事件、把权限请求整理成审批卡要显示的东西、把 `stopReason` 映射成任务状态）**拆成不碰子进程、不碰 Electron 的纯函数**，放 `src/main/connectors/acp-protocol.ts`，好单测。
- opencode 的启动参数和环境（`OPENCODE_CONFIG_CONTENT`：模型、`permission: ask`；只读任务用 `mode: "plan"`）参考第零批脚本，但**不要**再带 sikeoop 那个旧插件——ACP 已经给了轮次、文字、工具、权限，插件会和协议权限重复。

### 2.3 装配与回执

- `index.ts`：把 opencode 作为可选的 `agent` 执行体接进调度核心；权限回调接到现有灵动岛审批通道（统一审批路由仍按用户 10-10 决定暂缓）。
- 任务结束跑现有自动验收（`dispatch/verify.ts`），回执带上 sikeoop 量出来的 `files.changed/created/deleted`，不采信 agent 自述。
- 安全按方案第 7 节：永不传 `--auto`/`--yolo`/`--dangerously-*`；工作目录即启动目录；外部输出一律当数据，不从其文字解析命令。

### 2.4 进度与类型

- `shared/types.ts` 新增（只增）：`DispatchJob.progress?`（最近若干条进度）、`DispatchJob.result.files?`、一种进度事件 `DispatchEvent`。
- `preload`：如需要，新增读取进度的通道。

### 2.5 调度台显示（Claude 军团）

- 「外部 agent」任务显示流式文字和工具调用进度、权限卡、取消按钮。`dev-mock` 补对应部分。
