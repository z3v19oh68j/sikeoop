# 论文工坊第四批汇报：Quarto / Zotero 按需下载

日期：2026-10-11　范围：`docs/方案-论文工坊.md` 第 9 节

## 结论

代码写完了，但**没有真的下载并安装过一次**：没有启动应用，也没有下载完整的安装包（任务要求只读查询）。

- `npm run typecheck` 退出码 0。
- `npm test` 311 个全部通过（原 272 个，新增 39 个），连跑 3 遍结果一致。
- 没有启动应用，没有 git 提交，没有安装任何依赖。
- 三样东西（Quarto、Zotero、Better BibTeX）都不打包，都是用户点了才从官方地址下载。
- 仍然只在开发版可见。

现在能保证的：发布信息解析、按平台选包、校验、解压（含路径越界防护）、版本优先级、下载状态机，在假网络和手工拼的压缩包上是对的；其中解析和选包还对着 GitHub 今天的真实回答跑过。

不能保证的：主进程里真正发请求的那一小段（Electron 的 `net.request`）从没运行过。它要是有错，三样东西都下不下来。验收时请先在开发版里点一次「下载 Quarto」，见「没有实测的地方」第 1 条。

需要你定的事有 8 件，见最后一节。其中第 1 件（Better BibTeX 和 Zotero 的版本对不对得上）可能影响用户能不能用。

## 做了什么

### Quarto：托管安装

- **什么时候出现**：「引用与排版 → 排版」里，找不到 Quarto 或版本低于 1.4 时，出现「下载 Quarto」。
- **两次点击**：第一次点击只向 `api.github.com` 问最新版本，然后显示版本、大小、来源、许可（MIT，并写明包里有 Pandoc（GPL-2.0）、Typst、Deno 等组件）、校验方式、放在哪里。用户点「确认下载」才开始下。
- **下的是用户看到的那个版本**：确认前如果官方又发了新版，下的仍是界面上显示的那一版。
- **选包**：macOS 用 `quarto-<版本>-macos.tar.gz`（一个包同时支持两种芯片），Windows 用 `quarto-<版本>-win.zip`，Linux 按芯片用 `linux-amd64.tar.gz` 或 `linux-arm64.tar.gz`。
- **校验**：用 GitHub API 给的 `digest`（SHA-256）；老版本没有 `digest` 时改用发布里的 checksums 文件；两处都没有就不下载。下载完校验不通过，删除文件并报错。
- **解压**：解到 `userData/tools/quarto/<版本>/`，不需要管理员权限，不写系统目录。先解到临时文件夹，运行一次 `quarto --version` 确认能跑，再改名到位；跑不起来就不安装。该版本已经在了就直接复用，不联网下载。
- **进度、取消、重试**：显示已下载 / 总大小和百分比。取消会删掉下到一半的文件。网络中断会保留已下部分，再点「接着下载」从断点继续；服务器不支持续传时自动从头下。60 秒没有数据算中断。
- **优先级**：用户自己装的 Quarto（1.4 或更新）优先。只有用户没装、或装的太旧出不了 PDF 时，才用 sikeoop 下载的那份。
- **设置里**：「设置 → 编辑器与联网」多了一行「论文排版工具 Quarto」，能看到已下载的版本和位置、正在用哪一份、检查更新、删除、打开所在文件夹。更新装好后旧的那份自动删掉。

### Zotero：引导安装

「引用与排版 → Zotero」里，检测到没连上时给出两步。Zotero 没打开、且在常见安装位置也找不到时直接展开；找得到时折叠成一个链接。

1. **下载 Zotero**：向 `www.zotero.org` 的官方下载地址问到当前平台的安装包（它会转到 `download.zotero.org`），先显示版本、大小、来源、许可（AGPL-3.0）。确认后下载到用户的「下载」文件夹，下完用系统打开安装包（`shell.openPath`），安装由用户自己点完。Linux 的包是压缩包，不自动打开，只提供「打开所在文件夹」。
2. **下载 Better BibTeX**：从 GitHub `retorquere/zotero-better-bibtex` 的最新发布取 `.xpi`，核对 SHA-256 后保存到「下载」文件夹。界面写明在 Zotero 里「工具 → 插件 → 齿轮 → Install Plugin From File…」安装，并提供「打开所在文件夹」。发布说明里关于支持哪些 Zotero 版本的那句话会原样显示在确认框里。

两步做完有「都装好了，重新检测」按钮。全程没有静默安装。

### 只访问这些域名

| 用途 | 域名 |
| --- | --- |
| 问最新版本 | `api.github.com` |
| 下载 Quarto 包、checksums 文件、Better BibTeX | `github.com`，以及它转去的 `release-assets.githubusercontent.com`、`objects.githubusercontent.com` |
| Zotero 安装包 | `www.zotero.org`、`download.zotero.org` |

每一次跳转都先核对域名，跳到名单外的地址就停下，不会去访问。只走 https。

## 联网核对过的事实（2026-10-11，只读）

为了确认资产命名和校验格式，我发了这些请求，没有下载任何完整安装包：

- 两个仓库的最新发布信息（JSON）：Quarto 是 1.10.19，Better BibTeX 是 9.0.71。每个资产都带 `digest: "sha256:…"`。
- Quarto 的 checksums 文件（1 KB）：每行 `<sha256>  <文件名>`。我的解析代码对着这两份真实回答跑过，四个平台包的 `digest` 和 checksums 文件里的值一致。
- 三个 Quarto 包各取了前 256 KB 看内部结构：macOS 包顶层直接是 `./bin`、`./share`；Linux 包多套一层 `quarto-1.10.19/`，并且用了 GNU 长文件名；Windows 包顶层是 `bin/quarto.cmd`、`bin/quarto.exe`。我的 tar 读取代码对着 macOS 和 Linux 这两段真实数据跑过，能读到截断处为止。
- GitHub 的下载地址会转到 `release-assets.githubusercontent.com`，支持断点续传（返回 206）。
- Zotero 六个平台的下载地址都返回 302，转到 `download.zotero.org/client/release/10.0.6/<文件名>`；macOS 的安装包约 183 MB，支持断点续传。

包的大小：Quarto macOS 约 236 MB，Windows 和 Linux 约 140 MB；Better BibTeX 约 28 MB。

## 没有实测的地方

按风险从高到低：

1. **主进程里发请求的适配代码没有运行过。** 它在 `src/main/index.ts` 里（`paperToolRequest`），用 Electron 的 `net.request` 并设 `redirect: 'manual'`，写法对照了 Electron 自带的类型文档，但应用没启动过。它出错的表现是三样东西都下不了。
2. **没有解压过完整的真实包。** 真实包里如果有我没处理到的条目类型，解压会报错停下（不会装一半）。Windows 的 zip 一次都没对着真实数据跑过，因为 zip 的目录在文件末尾，我没有下载到那里。
3. **没有运行过解压出来的 Quarto。** 特别是 macOS：我的判断是 sikeoop 自己写出来的文件不带隔离标记，所以系统不会拦，但这只是推断。
4. **Windows on ARM 用 x64 包**是我定的（Quarto 没有发 ARM 版的 Windows 包），没有在那种机器上试过。32 位 Windows 不支持，会提示用户自己装。
5. **Zotero 的常见安装位置是凭记忆写的**（macOS 的 `/Applications/Zotero.app`、Windows 的 `Program Files\Zotero` 和 `%LOCALAPPDATA%` 下两处、Linux 的几个路径）。找不到只会让那两步默认展开，不影响功能。
6. **Zotero 里装插件的菜单路径是凭记忆写的**，没有对着 Zotero 10 核对。
7. **Zotero 安装包没有 SHA-256 可核对。** 我只看了下载地址的跳转，没有在那里找到校验值，也没有翻遍 zotero.org。现在的做法是只从官方域名走 https 下载，并核对文件大小；服务器不报大小就不下载。
8. **界面只过了类型检查**，没有在应用里看过。
9. **下载前没有检查磁盘剩余空间。**

## 测试覆盖了什么

任务点名的五类都有：

## 需要你定的事

1. **Better BibTeX 最新版和 Zotero 最新版可能对不上。** zotero.org 现在给的是 Zotero 10.0.6（方案里写的是 Zotero 8）。Better BibTeX 9.0.71 的发布说明写的是「兼容 Zotero 8 和 Zotero 9 beta，不再支持 Zotero 7」，没有提 Zotero 10。这句话可能只是没更新，也可能真的不兼容，我没法验证。现在的做法是把这句话原样显示给用户。另外，第三批定的「版本太旧」门槛是 Zotero 低于 7，而 Better BibTeX 已经不支持 7 了，建议改成低于 8（改一个数字）。
2. **下载用的是 `net.request`，不是方案写的 `net.fetch`。** 两者是 Electron 同一套网络（都走系统代理）。换的原因是 `net.fetch` 只能自动跟随跳转，拿不到中间地址，没法做到「只访问指定域名」。
3. **GitHub 的文件域名写死了三个。** GitHub 以后换域名的话，下载会停在「不在允许访问的地址里」，要改名单才能恢复。这是「只访问指定域名」的代价。
4. **Zotero 安装包和 `.xpi` 存到用户的「下载」文件夹**，没有放进 sikeoop 的数据文件夹。理由是这两个文件要用户自己处理，放在用户找得到、会自己清理的地方。Zotero 安装包下完会自动打开。
5. **更新后旧版 Quarto 自动删除。** 如果想保留旧版让用户自己删，去掉一行即可。
6. **动了 `settings/EditorSection.tsx`。** 第三批任务书说过别碰 `settings/**`（有军团成员在改），这一批的方案又要求设置里能管理。我只加了 3 行，卡片本身放在 `components/papers/` 里。如果和那位成员的改动冲突，请以对方为准，把这 3 行挪过去就行。
7. **取消下载会删掉已下的部分；网络中断则保留。** 也就是说「取消」不是「暂停」。
8. **又动了第三批的文件**：`quarto.ts`、`typeset.ts`、`TypesetPanel.tsx`、`CiteTab.tsx`、`typeset.test.ts`，以及模拟数据里 Quarto 没找到时的提示文字。请过目。
