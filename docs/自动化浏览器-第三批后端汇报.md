## 已实现行为

### 虚拟光标

click/fill/hover 在检查目标可操作、且非密码字段后调用显示钩子。通过顶层 frame 的 `Page.createIsolatedWorld` 与指定 contextId 的 `Runtime.evaluate` 注入显示层。光标移动 150ms，缓动 `cubic-bezier(.22,.61,.36,1)`；click 带 250ms 涟漪；fill 显示输入框矩形描边，700ms 后移除。跨 target 输入框坐标换算到顶层显示；旋转/倾斜情况下高亮是轴对齐近似矩形，不是精确四边形。

宿主与 shadow 内容均 `pointer-events:none`，宿主固定定位、最高常规 z-index `2147483647`、`aria-hidden`、`inert`、closed shadow root。显示脚本不调用 dispatchEvent、不修改输入值；真实事件仍由原 CDP Input 通道派发。最高常规 z-index 不保证盖过浏览器 top layer（例如原生模态 dialog）。

精简 AX 快照显式排除宿主与其 shadow 后代；DOM 命中检测设置 `ignorePointerEventsNone:false`，遵守叠层的指针穿透。序列结束/错误清理显示节点、新文档脚本与监听器；正常导航使用相同命名隔离世界的预注册脚本补装真实输入监听。切换 webview、销毁或崩溃会停止旧序列。截图仍可包含显示层的视觉效果；本批“快照排除”针对结构快照。

### 速度

现有 `browser/settings.json` 增加 `automationSpeed?: "demo" | "normal" | "fast"`。字段可选是为兼容旧设置与旧前端提交；实际默认 normal，旧客户端只提交 engine 时保留当前速度。

- demo：等待光标移动结束；click 同时等待涟漪结束，然后派发真实事件。高亮保留一段时间以覆盖输入操作，不要求等待其消失后再输入。
- normal：显示动画和真实事件并行；异步显示失败保守暂停，避免无提示继续执行。
- fast：不创建显示叠层；如果从显示档切到 fast，移除已有叠层。仍装输入接手监听，所以 fast 不等于不调用任何隔离世界命令。

后台动画有定时器兜底，避免仅等待 RAF/动画完成而永久挂起。

### 用户接手与状态机

`browser_act` 的原单动作和 actions 数组都经过 `BrowserService.runActions`。同一服务拒绝重入，清理结束前也不接受新的序列。

在对应 webview 的顶层、同进程子 frame 和已接入 OOPIF 中安装捕获监听：mousemove/mousedown/mouseup/wheel/pointerdown/keydown/keyup。通过限定 executionContextName 的 Runtime binding 回报固定字符串 `input`；主进程复核 session + executionContextId。不发送按键内容、输入值或页面事件详情。不是监听整个应用，也不是监听渲染端工具栏。

**真实输入区分：** CDP 派发的事件也是 trusted，不能仅靠 `isTrusted`。所有 `Input.dispatchMouseEvent` / `Input.dispatchKeyEvent` 统一携带 Unix epoch 秒数 `timestamp:1`；它早于 document time origin，DOM 时间戳应为负值或钳制为零。监听仅接受 trusted 且有限、严格大于零的时间戳，忽略自派事件及页面脚本 dispatchEvent。Input.insertText 不产生被监听的鼠标/键盘事件。时间戳为零的物理事件也会被忽略（例如极早、低时间精度的输入）；Electron/Chromium 对该标记的实际传递仍需真实 webview 验证，单测不是该行为的运行证明。

真实输入使 running → paused。真实事件本身不被拦截。暂停停在后续动作/变更命令检查点；当前已发送的 CDP 命令不会回滚。mouseReleased/keyUp 允许完成，避免留下按住的按键或鼠标。resume 从当前挂起位置继续，不重放已完成步骤。

stop 立即公布 error + `Browser automation stopped.`，唤醒暂停等待、中止 idle 等待并阻止后续动作。由于契约只允许 running/paused/done/error，停止使用 error，不新增 stopped。停止不回滚页面状态；已经发出的命令、页面脚本与已有审批对话框不能被撤回。若当前停在外部审批 Promise，工具返回需等审批 Promise 结束，但后续页面变更命令会被停止检查拒绝。

进度初始 step=0，动作步骤为 1-based；description 使用动作名和 ref（如 `fill [3]`），不放完整输入文字。最后成功为 done；失败为 error 并保留失败步骤与 reason。初始无序列状态为 done/0/0。step 是当前动作，不是已完成动作数；工具结果中的 completed 沿用“整个步骤成功返回”的计数。

## 前端用法

新增 SweetApi 均必选：

```ts
browserAutomationState(): Promise<BrowserAutomationState>;
browserAutomationResume(): Promise<BrowserAutomationState>;
browserAutomationStop(): Promise<BrowserAutomationState>;
onBrowserAutomation(cb: (state: BrowserAutomationState) => void): () => void;

interface BrowserAutomationState {
  status: "running" | "paused" | "done" | "error";
  step: number;
  total: number;
  description: string;
  reason: string | null;
}
```

IPC 请求：`browser:automationState` / `browser:automationResume` / `browser:automationStop`。
独立推送事件：`browser:automation`，载荷为完整状态；不复用原 `browser:event` 的 type 联合。

前端挂载时先订阅 `onBrowserAutomation`，再读取 `browserAutomationState()` 初始化；若读请求期间已收到事件，应优先使用事件状态，避免旧查询覆盖新状态。卸载调用返回的 unsubscribe。

状态栏显示 `正在：${description} · 第 ${step}/${total} 步`；paused 时显示“继续”，点击调用 browserAutomationResume；running/paused 时可显示“停止”，点击调用 browserAutomationStop。done/error 可收起或展示完成/失败原因。stop 后不会通过 resume 重新启动，需要 AI 再发新的动作序列。

速度选择沿用现有设置接口：

```ts
const { settings } = await api.browserState();
await api.browserSetSettings({ ...settings, automationSpeed: "demo" });
```

`api` 为已有 SweetApi 桥对象。renderer 负责真正的状态栏与速度选择 UI；本批没有创建这些组件。
