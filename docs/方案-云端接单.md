# 方案：云端接单（客户雇你做项目，sikeoop 辅助交付）

日期：2026-10-10　状态：**已归档，未开工**（用户决定先归档，之后再议）

## 1. 一句话

客户在云端平台付费雇你完成编程需求；你在 sikeoop 桌面版里接单，用自己的 Claude 工具（终端里的 Claude Code）在客户代码的隔离副本里干活，自动验收后由你确认交付，代码通过云服务器传回客户电脑，按 token 用量（或按单）结算。

## 2. 已澄清的边界

- 交付的是**你的工作成果**，Claude 是你的生产工具；不是把 Claude 的访问权转给客户，也不是转发客户的模型请求。
- 客户项目文件进、交付代码出，都是正常的数据传输。
- **接单与交付两步保留人工把关**：云端来单可以自动出现、自动整理成任务，但“接不接”“交不交”由你点确认，不做完全无人值守的自动接单、自动交付（符合个人订阅的使用方式，也保证质量）。
- 讨论中否掉的方向（记录在此避免重复讨论）：把个人订阅当作 API 转售给第三方、替客户转发模型请求——违反消费者条款，不做。若将来要做“agent 全自动在服务器上接单”，必须改用商用 API Key 或客户自带 Key。

## 3. 流程

```
客户（网页下单：需求 + 项目代码 + 预算）
        │  云端（Cloudflare Worker + R2，复用 hosting/）
        ▼
你的 sikeoop 桌面版「接单台」
  ① 自动识别：把需求整理成标准任务（目标、涉及文件、验收标准、预估量），不清楚的列出要问客户的问题
  ② 你确认接单 → 下载客户代码到隔离副本目录（先跑密钥扫描）
  ③ 调度核心把任务派给终端里的 Claude Code，在副本里干活
  ④ 自动验收：改动清单、越界检查、类型检查新增错误、汇报与事实对照
  ⑤ 你看一遍，确认交付
        │  云端
        ▼
客户收货：网页下载补丁/zip；或装了 sikeoop 的客户直接收到审批卡（批准才写入，可撤销）
按 token 用量（或按单）结算
```

## 4. 可复用的现有代码

| 环节 | 现成的东西 |
|---|---|
| 云端收单、存文件 | `hosting/`（Worker + R2，内容哈希存储、限额） |
| 派给 Claude Code 干活 | 调度核心 `src/main/dispatch/` + `CliExecutor`（排队、超时、取消） |
| 限定只改客户项目 | 任务的 `scope.roots` / `owns`（`dispatch/guard.ts`） |
| 交付报告 | 自动验收（`dispatch/verify.ts`） |
| 防客户代码密钥外泄 | `src/main/publish/scan.ts` |
| 用量计量 | sikeoop 自身调用：`usage/ledger`；Claude Code 的用量需另读：其 transcript 每条回复带 usage，Stop hook 可拿到 transcript 路径（`peers.ts` 已在读 transcript） |
| 订单进度 | 调度台 `DispatchConsole.tsx` |
| 客户端收货体验 | 桌面版审批卡 + 撤销这一轮；传输可复用 `relay/`（端到端加密） |

## 5. 需要新做的

1. 云端下单页与订单接口：提交需求、上传代码、看进度、下载交付物。
2. 桌面版「接单台」：新单提醒、任务卡片、接单 / 交付按钮。
3. 订单自动整理成任务（便宜模型抽取结构化字段 + 待澄清问题）。
4. 结算：按单汇总 token 用量，按单价出账；初期手动收款，不接支付。

## 6. 风险与注意

- 客户代码可能含密钥或机密：上传前扫描、只在隔离副本里工作、交付后按约定期限删除。
- 交付的代码绝不在客户电脑上自动执行，只以改动形式交给客户审批。
- 订单内容审核：拒绝恶意软件等请求。
- 计价：用订阅时你并不按 token 付费，token 只是计量工作量的尺子，单价需自定；或按单报价、token 作参考。
- 正式收钱前：收款资质、发票、代码版权归属写进服务协议，建议咨询专业人士。

## 8. 建议的启动顺序（开工时再确认）

1. 本地闭环：手动导入一个“订单”（需求 + 代码 zip）→ 接单台 → Claude Code 干活 → 自动验收 → 导出补丁。不碰云端。
2. 云端收单与下载交付物（复用 `hosting/`）。
3. 用量结算与账单。
4. 客户侧 sikeoop 审批卡收货、公开下单页。
