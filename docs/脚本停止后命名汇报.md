## 接口与行为

```ts
browserFlowStartRecording(name?: string, options?: BrowserFlowRecordingOptions): Promise<void>;
browserFlowStopRecording(name?: string): Promise<BrowserFlow>;
browserFlowRename(oldName: string, newName: string): Promise<void>;
```

上述方法均为 `SweetApi` 必选方法，不使用可选方法声明来绕过 mock 缺项。

1. 开始录制未传名称时生成 `未命名-<毫秒时间>-<随机后缀>`；显式传空字符串、null 或非法名称仍拒绝，不当作省略。
2. 开始时不保存脚本文件。停止传入 `name` 时直接以最终名称保存，JSON 内的 `name` 与文件名一致，不落地中间名称。
3. 停止不传名称时保留开始时名称，兼容原来的显式命名及无参数停止调用。仅传录制选项可用 `browserFlowStartRecording(undefined, options)`。
4. 停止保存采用现有排他写入机制：同目录临时文件加原子 `fs.link`，重名返回错误而不覆盖；保留原错误的 `EEXIST` 代码与消息片段。
5. 停止失败保留内存录制缓存，可换名再次停止保存；同步停止锁拒绝并发停止，保存成功后才清理缓存。
6. 改名加载源脚本、排他保存带新名称的 JSON，再删除旧文件，保留步骤、历史及创建时间。同名改名在确认源文件有效且存在后无操作成功；源缺失返回错误。
7. 改名期间阻止新的录制、回放、删除及再次改名；录制或自动化期间不能改名。
8. 名称白名单限制为字母、数字、下划线、空格、连字符，1–80 字符且无首尾空白；拒绝路径分隔符、点、控制字符、Windows 常见保留设备名及超过 255 字节的完整文件名。
9. 存储仍限定为当前项目的 `.sikeoop/browser-flows`，拒绝符号链接目录或脚本、非普通文件；停止绑定录制项目，改名固定初始项目并在存储操作中复核，防止切换项目后读写另一项目。

IPC 保持原 `browser:flowStartRecording`，给 `browser:flowStopRecording` 新增可选名称转发，新增 `browser:flowRename`。preload 与共享接口同步更新。

## 遗留问题与验证边界

- 改名不是跨两个文件的原子事务：新名称文件保存成功后，如果删除旧文件失败（包括此时项目切换），操作返回错误，可能在原项目留下两份有效脚本；不会覆盖目标或删除另一项目的脚本。未引入额外回滚删除。
- 既有路径检查不等于抵御恶意本地进程并发替换目录的完整文件系统隔离；本任务覆盖静态符号链接拒绝及可观测项目切换，不宣称消除所有外部 TOCTOU。
- 未启动 Electron、未运行真实 webview 或 UI/E2E；主进程 IPC 注册为静态断言，preload 转发为 fake Electron 边界上的运行验证。测试通过不等同于真实应用录制验证。
