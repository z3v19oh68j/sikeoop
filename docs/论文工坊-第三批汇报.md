## 结论

代码写完了，但**没有对着真的 Zotero 和 Quarto 跑过**：这台机器上两个都没装，任务书也不让联网装依赖。

- `npm run typecheck` 退出码 0。
- `npm test` 272 个全部通过（原 225 个，新增 47 个，8 个新测试文件），连跑 3 遍结果一致。
- 没有启动应用，没有 git 提交，没有安装任何依赖。
- 两个工具都没有打包，只调用它们的接口。Zotero 只访问 `127.0.0.1:23119`。
- 仍然只在开发版可见（新页签在 `PapersScreen` 里，整个论文工坊只在 `SHOW_UNFINISHED` 下挂载）。

所以现在能保证的是：解析、格式化、合并、命令组装、服务流程这些逻辑，在自编样例和假的 Zotero / Quarto 上是对的。不能保证的是：真实工具的回应和我按文档写的样例一致。验收时请在装了 Zotero（带 Better BibTeX）和 Quarto 的机器上实际走一遍，下面「没有实测的地方」列了最该先看的几处。

## 做了什么

新页签「引用与排版」，从上到下四块。另外「写作与润色」的输入框旁加了一个「从 Zotero 插入引用」按钮。

### Zotero（Better BibTeX）

- **检测与指引**：分四种状态——已连接（显示两个版本号）、Zotero 没打开、缺 Better BibTeX、版本太旧。后三种各给一句大白话原因和按顺序的操作步骤。只在第一次打开这个页签时检测，不会在应用启动时去碰 23119 端口。
- **插入引用**：调起 Zotero 自己的引用选择框（CAYW），可以填页码和前后缀。写法跟着文件走：`.tex` 用 `\cite{key}`，其余用 `[@key]`，也可以手动切换。结果有三个去向：插到编辑器当前文件的光标处、放进写作页输入框、复制。
- **检索文献库**：按标题、作者、年份搜（JSON-RPC `item.search`），勾选后生成引用。
- **references.bib 同步**：两种方式——只拉文稿里引用到的文献，或拉整个 Zotero 集合。只新增和更新，不删除，手动加的条目原样保留。写入前先问用户，并列出会被替换的条目。没有变化时不问也不写。Zotero 里找不到的引用 key 会单独列出来。
- **导入 PDF**：把条目的 PDF 附件读进论文工坊，带上 Zotero 的标题、作者和 citekey。之后转证据库时，记录的 `ref` 就是 citekey（有测试）。同一个 citekey 再导入不会重复读。

### Quarto

- **检测与指引**：先找 PATH，再找各系统安装包的常见位置，找到后运行 `quarto --version` 显示版本。没找到给安装步骤；版本低于 1.4 时说明出不了 PDF。
- **一键排版**：`.qmd` / `.md` 排成 PDF（走 Typst）、Word 或网页，输出在文稿旁边。每次排版是调度核心上的一个任务，可以取消，10 分钟超时。同一篇文稿的排版排队执行，不会并发。
- **失败给要点**：从 Quarto 的输出里挑出错误行和值得处理的警告（Typst 错误带文件行号、找不到引用、YAML 写错等），去掉堆栈；对字体缺失、找不到参考文献文件等常见原因再补一句怎么办。原始输出折叠在下面。
- **论文模板**：标题、作者、摘要、语言、`references.bib`、引用格式。中文默认 GB/T 7714-2015，英文默认 APA，可改。只新增文件，不覆盖已有的，添加前先问。
- **实时预览**：打开后，每次保存文稿自动重排。排版中途又保存多次，只会再排一次。同时只盯一篇文稿。
- **打开输出**：网页在 sikeoop 的内置浏览器里打开；PDF 和 Word 用系统里的程序打开。

### CSL 文件的来源与许可（已核对）

**没有随附，改为首次使用时下载。** 核对结果：

| 样式 | 文件 | 来源 | 许可 |
| --- | --- | --- | --- |
| GB/T 7714-2015（顺序编码制） | `china-national-standard-gb-t-7714-2015-numeric.csl` | CSL 官方样式库 `citation-style-language/styles` 的 master 分支 | CC BY-SA 3.0 |
| APA 第 7 版 | `apa.csl` | 同上 | CC BY-SA 3.0 |

- 两个文件我都实际请求过，确认存在（HTTP 200）；GB/T 文件头里的 `<rights>` 行写的就是 CC BY-SA 3.0。另一个猜测的短文件名 `gb-t-7714-2015-numeric.csl` 不存在（404），没有用。
- 下载前界面会说明来源、许可、访问哪个域名，用户勾选后才下载。
- 文件原样保存，不改内容，所以文件里自带的作者署名和许可说明都保留。代码会检查下载到的确实是带 `<rights>` 的 CSL 文件，不是的话不保存。
- 下载一次后存在 `userData/papers-csl/`，以后新建论文直接复制，不再联网。
- 用户不下载也能建论文：PDF 用 Typst 自带的同名格式（`gb-7714-2015-numeric` / `apa`，已在 Typst 文档里确认这两个名字存在），Word 和网页先用 Pandoc 默认格式。

## 没有实测的地方

接口的写法我对照官方文档核对过这些：CAYW 的参数和 `probe` 返回 `ready`；JSON-RPC 的方法名、参数和返回类型（`api.ready`、`item.search`、`item.attachments`、`item.export`、`user.groups`）；pull export 的地址格式；Quarto 的 Typst 格式支持 `csl`（文件或内置名）和 `citeproc`；Typst 内置样式名。

下面这些文档里没写清楚，或者我没能查到，是按经验写的，最该先实测：

1. **CAYW 取消时返回什么。** 文档没说。我按「返回空内容 = 没选」处理。
2. **`item.search` 和 `user.groups` 返回的具体字段。** 文档只写了 `any`。解析时兼容了几种常见写法（`citekey` / `citationKey` / `citation-key`；集合平铺或嵌套），但真实字段可能还有出入。
3. **`item.export` 的格式名。** 先传 `biblatex` / `bibtex`，报错里带 translator 字样时改传全名 `Better BibLaTeX` / `Better BibTeX` 再试一次。
4. **key 不存在时 `item.export` 的行为。** 我按「整批拒绝」处理：被拒绝后逐个 key 再请求，找出缺的那几个。
5. **集合导出地址。** 先用文档里的 `/better-bibtex/collection?/<库>/<集合>.<格式>`，404 时改用新版菜单给的 `/better-bibtex/export/collection?…`。
6. **`Zotero-Allowed-Request` 请求头。** 凭记忆加的，用来避免 Zotero 把请求当成网页请求拒掉。主进程用的是 Node 自己的 fetch，User-Agent 不是浏览器，大概率本来就不会被拒。
7. **`quarto render … --no-execute`。** 这个参数我记得在 `quarto render --help` 里有，但这次查的两个文档页都没提到。如果不认，默认排版会直接失败。
8. **「Output created: …」这一行。** 用它定位输出文件；没有这一行时退回「文稿旁边同名文件」。
9. **Windows。** `quarto.exe` 直接运行；只找到 `quarto.cmd` 时要经过 cmd.exe，这时文件名里带 `" % ^ & | < > !` 的会被拒绝。取消用 `taskkill /T`。都没在 Windows 上跑过。
10. **模板的中文字体。** macOS 写 `Songti SC`，Windows 写 `SimSun`，Linux 写 `Noto Serif CJK SC`。电脑上没有这个字体时 Typst 会报错，失败要点里会提示改 `mainfont`。

本机实测过的只有两样：进程运行器（用 node 自己当被运行的程序，验证了输出、退出码和中途停止）和文件监视（macOS）。

## 顺手修掉的问题

- **第二批的竞态：刚结束就删除，记录会重新出现。** 这是我上一批为了修「刚结束读成失败」引入的窗口：记录在内存里已经显示完成，但最后一次写盘还没落地，这时删除会被随后的写盘盖回来。这次全量测试偶发失败时发现的。审稿和选题两个服务都改成：删除先等在途的写盘结束，再删文件，并且删除后不再写。相关测试连跑 6 遍通过。
- **文件监视会收到不相干的事件。** macOS 会把开始监视前一刻的改动也报过来，Quarto 往文稿旁边写输出也会触发目录事件。改成只有文稿自己的修改时间或大小真的变了才算一次保存。

## 需要你定的事

1. **排版任务在调度台里显示成「cli」类。** `DispatchExecutorKind` 只有 `cli / session / model` 三种，加新种类要同时改 `DispatchConsole.tsx` 里的标签表，而那个文件这次不让碰。所以 `QuartoExecutor` 暂时报 `kind: "cli"`、名字 `Quarto`。如果你想要单独一类（比如 `process`），需要在 `shared/types.ts` 和 `DispatchConsole.tsx` 各加一行。
2. **「可在 sikeoop 里打开」目前只对网页成立。** 网页输出走内置浏览器；PDF 和 Word 是交给系统程序打开的。PDF 能不能在内置浏览器里直接看，取决于那边有没有开 PDF 查看，我没有去动浏览器部分。要不要让 PDF 也在 sikeoop 里看，由你定。
3. **实时预览是「保存后重排」，没有用 `quarto preview`。** `quarto preview` 会自己起一个本地网页服务并打开系统浏览器，和「每次渲染是可取消的调度任务」不好对上。方案里两种都允许，我选了重排。重排后不会自动刷新已打开的输出，要用户自己再点一次打开。
4. **默认不运行文稿里的代码块。** `.qmd` 里可以有 R / Python 代码，排版时默认加 `--no-execute`，界面上有一个勾选项才会运行。理由是：点「排版」或者只是保存一下文件，不应该顺带执行代码。需要注意，这拦不住项目自己的 `_quarto.yml` 里配置的脚本和 Lua 过滤器，那些 Quarto 照样会跑。
5. **写入 references.bib 和新建论文的确认，是新加的一个函数。** 现有的 `approveExport` 弹窗文案写的是「只新增文件，不覆盖已有文件」，对同步 .bib 不成立，所以在 `index.ts` 里按同样的方式（灵动岛开着走灵动岛，否则弹对话框）另写了 `approvePaperWrite`，文案如实。没有改已有的审批流程；如果你认为这也算审批流程的一部分、应该并进去，请告诉我。
6. **「版本太旧」的判断标准是我定的**：Better BibTeX 没有 `api.ready` 这个方法，或者 Zotero 主版本低于 7。方案里写的是「Zotero 8 插件」，但 Better BibTeX 在 Zotero 7 上也能用，所以没有卡到 8。要卡到 8 改一个数字即可。
7. **又动了前两批的文件。** 第一批 `service.ts` 加了 `importFromZotero` 并改了证据 `ref` 的取值（没有 citekey 的论文行为不变）；第二批 `review.ts`、`ideas.ts` 修了上面说的竞态。都请你过目。
