## 构建配置与兼容

新增常量：

```text
__SIKEOOP_BUILTIN_FREE_PROVIDERS__
  ← process.env.SIKEOOP_BUILTIN_FREE_PROVIDERS ?? "[]"
```

该环境变量为 JSON 数组，每项结构：

```json
[{"id":"alpha","name":"内置供应商 A","baseUrl":"https://example.invalid/v1","key":"test-placeholder","protocol":"openai"}]
```

示例只使用假地址和测试占位字符串，不包含实际供应商地址或真实 Key。

- 接受 OpenAI / Anthropic 两种协议；要求非空名称、Key、有效 HTTP(S) baseUrl 和安全的供应商 ID。
- 拒绝 URL userinfo、query、hash；规范化尾部斜杠。非法 JSON/非数组记一行日志，非法或重复项各记一行日志，只包含固定原因与数组索引，不插入输入值、Key 或异常体。
- 注入 ID 统一为 `builtin-free-<id>`；已经为 `builtin-free` 或 `builtin-free-*` 时保持。避免与普通预设及自定义供应商 ID 冲突。
- 同 ID 或同协议、同规范化 baseUrl 去重，数组中首个有效项优先。
- 保留 `__SIKEOOP_BUILTIN_FREE_BASE_URL__` 和 `__SIKEOOP_BUILTIN_FREE_KEY__`。两个旧值均非空且地址有效时合并为 `builtin-free`；与新数组重复时新数组优先，不再追加旧项。
- 每项默认 `defaultModel: "auto"`、`discoverModels: true`、`builtinFree: true`。Anthropic 采用现有兼容 Messages adapter；模型发现沿用协议发现层。
- 用户保存的 Key 仍优先于构建注入；Key 不进入 ProviderView 或 IPC 返回值。

## 设置接口（仅新增）

```ts
// RoutingSettings
builtinFreeOrder?: Partial<Record<EffortPurpose, string[]>>;

// ProviderView
builtinFree?: boolean;
enabled?: boolean;

// ProviderUpdate
enabled?: boolean;

// SweetApi：必选，不是可选方法
setBuiltinFreeProviderEnabled(providerId: string, enabled: boolean): Promise<ProvidersState>;
```

IPC：`providers:setBuiltinFreeEnabled`。只允许对内置免费供应商保存布尔开关；也可通过既有 `updateProvider({ id, enabled })` 写入同一设置。

- 开关保存在 providers.json 的 overrides[id].enabled；缺省开启，false 关闭。
- `routing.builtinFreeOrder` 通过现有 `setRouting` 保存。每种用途独立的供应商 ID 数组，首项优先；缺省或未列出的供应商按构建预设顺序补到末尾。重复 ID 去重，未知 ID 不产生候选。传入 `{}` 可清除自定义顺序；旧前端遗漏字段时保留已有顺序。
- 示例：`{ chat: ["builtin-free-beta", "builtin-free-alpha"], hard: ["builtin-free-alpha"] }`。
- 关闭项仍出现在供应商设置列表中，带 enabled=false，但不参与发现、auto 选择、failover、ready 引用或群聊候选。固定模型直接指向关闭项时明确拒绝。

## auto 路由与 failover

- 选中内置免费供应商的 auto 后，请求准备阶段发现全部已启用且配置完整的内置供应商；按用途顺序依次选可用供应商。某家发现为空可直接选下一家，不把 auto 字符串交给 SDK。
- 每家均复用相同用途的名称启发式：chat/compress/subtask 轻量，coding 编程主线，hard 强推理。供应商顺序优先于跨供应商名称比较，不声称知道实际价格/能力。
- 主会话与 complete/stream、审批、识图等既有 withAutoFailover 调用共享供应商池。普通非内置供应商的 auto 保持原来的供应商内选模及 failover；显式固定模型不自动进入内置池。
- 429、402、401、403、408、5xx 和已有可重试连接/超时错误视为供应商级失效，直接去下一供应商，不在该供应商的其他模型上浪费重试。
- 404 先按该供应商的模型发现顺序尝试其他模型，再跨供应商。每家首先尝试同用途选中模型，再保留其余发现顺序。
- 主会话保留既有 handoff 和 tried-set，并按本轮记录失效供应商；辅助请求也跳过本次已失效供应商。全部耗尽时保留最后请求错误。
- 非重试错误、取消不 failover；stream 已输出文本时不重放。辅助请求剩余候选在 retry 前重新检查开关，途中关闭的供应商也会跳过。
- 独立开关不会取消已在途的网络调用；后续准备/候选选择使用实时设置。下一轮会重新按优先顺序选择，没有新增持久化故障熔断状态。

## 仓库外 env 与安装包边界

`npm run build` 从脚本所在仓库根目录解析固定位置 `../.secrets/sikeoop-builtin.env`，而不是依赖调用者 cwd。dist:win/dist:mac/dist:all 都经同一 build 脚本加载。

- 文件不存在（ENOENT）跳过。其他读取错误使用固定错误信息终止，不打印 OS 异常或内容。
- 只读取 `SIKEOOP_BUILTIN_*` 变量，支持 export、单双引号、注释与单行 JSON。不会 source、eval、展开 shell 命令或复制 env 文件。
- 调用者已有环境变量优先于文件，包括显式空值。
- 没有读取或展示用户本机真实 secrets 文件；测试以注入读取函数覆盖存在/缺失/读取错误。

静态确认 electron-builder files 仍为：

```json
["out/**", "package.json", "!**/*.map"]
```

extraResources 仅为已有 `resources/` 子目录。没有包含仓库外路径、`.secrets`、env 文件或脚本的打包配置；新增单测锁定这些条件。因此该 env **源文件不进入安装包**。本次未实际打包或检查安装包。
