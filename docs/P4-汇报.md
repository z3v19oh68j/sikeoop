### 做了什么

- 新建 `session/service.ts`，实现 `CrossSessionApi` 的 10 个操作，全部返回 `SessionResult`，入参按 `unknown` 做运行时校验，不抛异常。
- **@ 派活走调度核心**：用户每 @ 一个成员提交一个 job（origin `session`，`scope.roots` = 成员启动时的目录）。成员之间的 send_to 也提交为 job，`parentId` = 发送方当前 job。
- **单发言人**：改了 `scheduler.ts`，`SubmitInput` 增加可选的 `lane`，同一 lane 的 job 一次只跑一个、按提交顺序。session 的 job 用 sessionId 作 lane。`lane` 只存在调度器内部的 Entry 上，没有改 `DispatchJob` 类型。已补 2 个调度器测试。
- **预算**：沿用调度核心 origin `session` 的默认预算（每棵树 20 个 job）。用完时时间线插 `hopLimit`，send_to 把拒绝理由返回给发送方。用户再发言就是新的根任务。
- **越界**：PreToolUse 里凡是带 `file_path` / `notebook_path` / `path` 的工具都过 `checkScope`（realpath），越界返回拒绝理由并插 `outOfScope`（带 `dir`，供“加入此目录”按钮用）。文件锁冲突插 `lockDenied`。
- **Stop**：成员回复写成 `agent` 事件；成员退出插 `agentExited` 并标 exited。
- **持久化**：用现成的 `SessionStore`。重启后成员标 exited（store 原有逻辑），测试覆盖了。
- `index.ts`：PeerBus 传入 `onSessionEvent`；注册 10 个 `session:*` IPC；推送 `session:event` / `session:changed`；装配 `buildSessionLaunch`。
- preload 换成真实 IPC，删掉 `SESSION_NOT_READY`；dev-mock 换成能演示的内存实现（成员加入、@ 后依次回复并显示排队、消息里带“越界”会出越界卡片）。
- `crossSession.ts` 删掉复制的类型，改从 `@shared/types` 转出；`sessionApi()` 只找 `window.sweet.session`。
- `docs/cross-session-spec.md` 按 D4 改写（MAX_HOPS → 任务树预算；`window.api` → `window.sweet`）。

### 偏离任务书或规格的地方（请指挥官确认）

1. **测试放在 `test/dispatch/` 而不是 `test/session/`**。`npm test` 只跑 `test/dispatch/`，而 `package.json` 不在我的归属里。要挪到 `test/session/` 需要改 `package.json` 的 test 脚本。
2. **job 的 `scope.roots` 用成员启动时的目录，不是 session 当前的目录**。两者只在“成员启动后又加了目录”时不同。用当前目录的话，派活前检查会因为“这个 CLI 写不了新目录”把该成员之后的所有任务都拒掉。越界判定（`checkScope`）用的是 session 当前目录。
3. **一次发言 @ 多个成员，每个成员各是一棵树**，各有 20 的预算，没有共用一棵。调度核心没有“无执行体的根任务”，要共用就得让第一个成员当其他人的父任务，停它会连带停掉别人。
4. **session 成员的 Bash 在 PreToolUse 里直接拒绝**。`buildSessionLaunch` 的启动横幅和系统提示都写了“shell 禁用”，但原来没有任何地方真的拦，Bash 会走到灵动岛审批、用户一点就放行。这不是改审批流程，是补范围拒绝；不想要可以删 `service.ts` 里的一行。
5. **时间线事件的 `from` / `to` 写成员名（`Claude-1`），用户写 `user`**，不是 agentId。面板的 `nameOf` 两种都认；用名字的话成员被移出后历史还读得出是谁。`send` 的 `mentions` 入参仍是 agentId。
6. **改了面板一句文案**：hopLimit 卡片标题原来写死“已达 5 次”，D4 之后不对了，改成“AI 之间互相派活的次数用完了，先停住了。”没有动样式。
7. **没被任何 job 占着的成员不能 send_to**（比如被用户叫停后还在说话的成员），返回拒绝理由。否则叫停之后它还能开出一棵带满额预算的新树。

### 没做的 / 存疑的 / 需要决定的

1. **“在终端里查看”没接通**。`openTerminal` 现在返回 `{ ok:false, message:"只读查看成员终端的界面还没接上" }`。`TerminalPanel.tsx` 里没有 `s:…` 的标签，收到 `term:focus` 会直接忽略；`TerminalHost` 也不缓存输出，后附着看不到之前的内容。需要改 `TerminalPanel.tsx` 和 `terminal.ts`，都不在我的归属里。申请归属，或交给 ui-engineer。
2. **因为上一条，成员启动时如果 CLI 弹交互提示（比如 Claude Code 的“是否信任此目录”），用户没有地方回答**，成员会一直停在“启动中”。这一点我没法在不启动应用的前提下确认，是这一步最大的风险。
3. **“停止”只取消 job、清空队列，不会打断终端里正在进行的那一轮**。成员会把当前这轮说完，回复照常进时间线，然后才空闲；这期间 lane 已经放开，下一个成员可能同时开始。这和调度台的取消是同一个行为（`CliExecutor` 没有中断能力）。要真打断得往终端发 Esc 并让 PeerBus 把状态改回空闲，涉及 `peers.ts` 的非 group 部分，而且我不确定 Claude Code 被 Esc 打断后会不会触发 Stop hook。
4. **exited 的成员不能原地重新拉起**，接口里没有这个操作。现在的做法：重启后再拉入同类 CLI，新成员会重新叫 `Claude-1`，顶替列表里同名的 exited 成员。
5. **session 成员会出现在灵动岛和 `term:agents` 列表里，且没有 session 名前缀**（规格要求加）。`AgentSessionView` 没有 group 字段，加前缀要改共享类型和 `peers.ts` 的 `view()`，没动。
6. **Codex 越界的事后检测没有单独做**。规格写“fs.watch / 回复扫描补事件”；现在靠的是 job 带了 `scope.roots` 后调度核心自带的验收（改动范围检查），结果在调度台的 `job.checks` 里，不会变成时间线上的 `outOfScope` 事件，而且它只看 roots 以内的改动。
7. **MCP 初始化时给成员的说明没有带目录**（`peers.ts` 的 `rpc initialize` 调 `peerPrompt(s.name)`，没传 roots）。Claude 成员另有 `--append-system-prompt` 说明了目录，影响不大，没动。
8. **新建 session 的目录必须是当前打开的项目或“最近项目”之一**（规格里的“最近项目/已授权列表”，现在没有单独的授权列表）。`addRoot` 以原生确认框为授权，不要求在最近项目里。

## P4a 补二（2026-10-10，执行：终端 Claude Code CLI）

## 结果：完成（代码与单元测试）；界面未实测

没有启动 Electron，也没有跑 dev:web。下面两项在窗口里的样子都没看过，只过了 typecheck；退出通知的判定逻辑有单元测试。

### 做了什么

**1. 成员被移出 / session 结束后，只读标签显示“已退出”**

- **原因怎么带过去**：现成的 `term:exit` 只有 `(tab, code)`，带不了文字，preload 也不在归属里。做法是用 `code` 带：主进程自己结束成员进程时发约定的负数，`-101` = 被用户移出，`-102` = session 结束。进程自己退出时发的是真实退出码，不会是负数，所以不会撞。这两个数在 `shared/types.ts` 里定成类型 `MemberExitCode`，主进程和界面两边都受它约束。
- `service.ts`：`closeTab` 多带一个原因（`"removed"` / `"ended"`）；新增纯函数 `memberExitCode(tab, why)`，只有形如 `s:<sessionId>:<agentId>` 的标签才返回通知码，其他标签返回 null。
- `terminal.ts`：`kill(tab, notice?)` 多一个可选参数，给了才发 `term:exit`。**普通终端标签的关闭行为没变**：所有原有调用都不传这个参数，照旧不发。
- `TerminalPanel.tsx`：只读标签的遮罩现在写明原因——
  - `<名字> 已退出：你把它移出了 session`
  - `<名字> 已退出：这个 session 已经结束`
  - `<名字> 已退出：它自己退出了（退出码 N）`
- 三种情况的覆盖：移出和结束走上面的通知码；成员自己退出本来就会发 `term:exit`（真实退出码），现在只读标签会把它显示成“它自己退出了”。

**2. 浏览器预览（dev-mock）里查看成员终端**

- mock session 的“查看”现在会打开一个假的只读终端：先回放一段启动输出（Claude Code 或 Codex 的横幅、工作目录、一行“已连上”），之后每 3 秒追加一行工作日志。
- “临时允许输入”可以演示：打开后打的字会回显，回车换行，退格可用。
- mock 里移出成员或结束 session，已打开的只读标签会显示对应的“已退出”原因。
- 走的是和真实主进程一样的流程（`term:focus` → 标签上报尺寸 → 复位符 + 回放 → 实时输出），`TerminalPanel.tsx` 里没有为 mock 写任何特殊分支。
