# 方案：深度科研（接入 Chain-Centric）

日期：2026-10-11　状态：S1 后端、S2 界面已完成（代码 + 单元测试，未实跑）；实跑测试交给用户

## 1. 目标

在 sikeoop 里加一个面向用户的「深度科研」功能：输入一个研究问题（可附证据库），由 5 个不同家的模型做对抗推理，得到「未审查 / 共识 / 争议 / 崩塌」四区结论图。

**约束（用户 2026-10-11 定）**：Chain-Centric 源码一行不改，sikeoop 侧最小改动。

## 2. 被接入的模块

- Chain-Centric v0.5.0（MIT，作者 Zhenyu Dai），Python ≥ 3.10，依赖 numpy / scipy / scikit-learn / pydantic / click / rich，可选 openai / anthropic。
- 入口：`chain-centric run -q <问题> [-r 证据.json] [-o 输出.json] [--checkpoint 进度.json] [--max-rounds N]`。
- 配置全走环境变量：`CHAIN_CENTRIC_AGENTS=provider:model,...`、`CHAIN_CENTRIC_EVIDENCE_LLM`、`CHAIN_CENTRIC_MAX_ROUNDS`，以及各家 `XXX_API_KEY`（anthropic / openai / deepseek / minimax / kimi / glm / mimo / doubao / qwen）。
- 来源：微信收到的 `Chain-Centric-Windows-Test-Package-20260706.zip`（仅读过 README、pyproject、requirements、cli.py、config.py，未解压、未运行）。

## 3. 最小接入方式（源码不改，只在外面包一层）

```
「深度科研」页面 ──IPC──▶ 主进程 research 服务 ──调度核心任务──▶ 子进程：python -m chain_centric.cli run …
     ▲                                                       │  env：sikeoop 注入的 Key 与模型
     └──────── 进度（读 checkpoint / 输出流）、结果（读 -o 输出 JSON）──┘
```

1. **随包带源码**：原样放进安装包资源目录（含 LICENSE、署名），不改任何文件。
2. **Python 环境**：首次使用时在 `userData/deep-research/venv` 建虚拟环境，`pip install <包目录>[llm]`，并补装 `requirements.txt` 里有、`pyproject` 里缺的依赖（httpx、aiohttp、jsonschema）。优先用 `uv`（快），没有就用系统 `python3`；两者都没有时，界面给安装指引。安装前征得同意，显示进度。
3. **运行**：只用 `run` 子命令（`demo` 写死 `/tmp`，Windows 不可用）。
   - 工作目录设为本次运行的专用文件夹，避免读到别处的 `.env`。
   - `CHAIN_CENTRIC_AGENTS` 和各家 Key 由 sikeoop 用环境变量显式传入（显式传入的优先于它读到的 `~/.chain_centric.env`）。
   - 默认模型由 sikeoop 传，不用它内置的旧默认值。
4. **调度核心**：每次运行是一个任务（`session` 执行体，跑子进程），在调度台里能看到进度、耗时，能取消（结束子进程），有超时。
5. **花费与隐私**：开跑前弹确认卡，列出 5 个模型、轮数上限，说明“问题和证据会发给这 5 家服务商”；同一项目第一次使用时单独征得同意（同 Jev）。
6. **结果**：读 `-o` 输出的 JSON，在页面上画四区图（共识实心、争议空心、崩塌打叉、未审查虚线），点开一条看攻击次数、存活率、推理链。结果按项目保存，可重新打开。

## 7. 侦察后的修订（2026-10-11，依据 `docs/深度科研-侦察报告.md`）

### 7.1 方案要改的地方（仍然不改它的源码）

| # | 原方案 | 改为 | 依据 |
|---|---|---|---|
| 1 | 读输出 JSON 画四区图 | 四区只是渲染好的一段文字。由 sikeoop 按报告 2.3 节的公式，从 `claims` + `chain_details` 自己重算每条命题的区、攻击次数、存活率 | 发现 A |
| 2 | 补装 httpx、aiohttp、jsonschema | 不需要，`pip install <包>[llm]` 即可 | 发现 I |
| 3 | 轮数上限走环境变量 | 只能用 `--max-rounds` 传（环境变量会被命令行默认值 30 覆盖） | 发现 C |
| 4 | 工作目录设为专用文件夹 | 另外把子进程的 `HOME`（Windows 为 `USERPROFILE`）指到本次运行的专用文件夹：它写死往主目录写的 `semantic_snapshot_R*.json` 会落在那里，也读不到用户的 `~/.chain_centric.env` | 发现 D、第 8 节 |
| 5 | — | 子进程固定加 `PYTHONUTF8=1` 和 `python -u`：防 Windows 编码崩溃，并让输出不缓冲、可逐行读进度 | 发现 E、H |
| 6 | 进度读 checkpoint | **不开 `--checkpoint`**（开了每轮多一次不计数的模型调用）；进度改为逐行解析它的普通 `print` 输出（轮数、攻击、`call failed`） | 发现 G、H |
| 7 | — | 开跑前由 sikeoop 校验 5 个模型的 Key 都在、名字都对；跑的过程中遇到 `call failed` 行，界面提示是哪家出错 | 发现 F |
| 8 | — | 它标的“已核实”引用不等于真的核实过（证据搜索并不联网）。界面上显示为“模型提供的引用，未核实” | 发现 J |
| 9 | — | 原始输出可能含打码的 Key 片段：只解析，不原样保存或展示 | 第 8 节 |
| 10 | 取消：结束进程 | 取消时结束整个进程树（Windows 同样）；调度核心任务必须设超时（某家接口不响应会一直等） | 第 8 节 |
| 11 | 确认卡只列模型和轮数 | 加调用次数估计：5 个模型时，12 轮约 70–110 次，30 轮约 180–270 次 | 第 7 节 |

### 7.2 可能放宽的限制

`openai` 这一家调用 SDK 时没有传接口地址，SDK 可能会读环境变量 `OPENAI_BASE_URL`。如果实测成立，就能接**一个** OpenAI 兼容的中转站（发现 K，未确认）。

### 7.3 需要实跑才能确认的事（用户决定是否做）

报告第 9 节有 8 项只读代码确认不了，最要紧的是：Windows 上加 `PYTHONUTF8=1` 后能否跑完、`HOME` 指走后有没有副作用、`OPENAI_BASE_URL` 是否生效、实际调用次数和 token。

建议的**最小试跑**（需要用户同意，因为会运行这份第三方代码，并花用户自己 Key 的钱）：
- 在 scratchpad 的独立目录里建虚拟环境、安装；`HOME` 指向该目录；
- 2 个便宜模型（如 DeepSeek + 通义）、`--max-rounds 3`、用它自带的一个小预设；
- 预计几十次调用；记录调用次数、耗时、输出结构，结果写进侦察报告；
- Windows 那一项需要在 Windows 机器上另跑一次。

### 7.4 用户决定（2026-10-11）

- **Chain-Centric 作为独立的子进程运行**：sikeoop 只负责拉起、传参与环境变量、读输出、结束进程；不在 sikeoop 进程里加载它的任何代码，也不通过 MCP 常驻。
