## 1. 它是什么（只读审阅摸清的）

- **入口**：bin `rea` / `rea-agents` → `scripts/rea.mjs`（纯分发器）。
  - `rea mcp` → 载入 `dist/main.js` 起 **stdio 上的 MCP 服务**（JSON-RPC）——这是 sikeoop 要用的方式。
  - `rea mcp doctor` → 诊断；其它参数 → CLI。
  - `rea setup` → 只是一个 CLI 子命令，**配置 Hopper 与各 agent**（写 agent 配置）。**本方案绝不调用它。**
- **Node 要求**：`engines.node = ^22.19.0 || ^24.11.0 || >=26.0.0`。本机 node 26.10 满足；**但这是硬性前提**（见第 6 节决策 D2）。
- **配置目录**：`$XDG_CONFIG_HOME/rea`（默认 `~/.config/rea`）。给子进程设独立 `XDG_CONFIG_HOME` 即可隔离，不碰用户全局配置。
- **外部工具按需、全可选、经环境变量指定**（`REA_*`）：
  | 用途 | 外部工具 | 必需性 |
  |---|---|---|
  | 原生反编译伪代码 | Ghidra / IDA / Hopper（三选一） | 原生分析才需要；都可选、用户自备 |
  | 安卓 APK 代码 | JADX（jadx-headless-mcp jar）、apktool、adb | 可选 |
  | 固件解包 | Binwalk / Unblob（Linux） | 可选 |
  | 离线 ELF / 崩溃核 | pwntools / pwndbg(gdb) | 可选 |
  | 浏览器/Electron/进程 动态观察 | playwright 的 Chromium、node-pty、lldb、mitmproxy | 可选、且属「运行时捕获」（见第 5 节） |
  | **纯静态 JS/Electron/.NET/EVM/PE/plist** | 无需任何外部引擎 | 开箱即用 |
- **MCP 工具约 170 个**，分两类（对安全设计很关键）：
  - **静态只读类（绝大多数）**：`open_binary`、`inspect_*`、`analyze_javascript_application`、`inspect_android_package`、`inspect_managed_artifact`、`procedure_*`、`list_*`、`decompile`、`compare_*`、`get/export_evidence_bundle` 等——只读目标文件，安全。
  - **运行时/捕获类（少数，高风险）**：`capture_browser_scenario`、`capture_electron_scenario`、`capture_process_scenario`、`capture_native_ui_scenario`、`observe_*`、`trace_native_ui_action` 等——**会执行或附加到目标程序**。
- **审批**：SKILL 明确「REA 自己不要求审批标志，由 agent 客户端决定审批」。正好交给 sikeoop 的 MCP 审批 + 审批卡把关。
- 权威工具清单在仓库 `docs/mcp-contracts.md#generated-catalog`（未打进 npm 包），由 `scripts/generate-mcp-tool-catalog.mjs` 从工具定义生成。

## 2. 最小接入方式（源码不改，外面包一层）

```
「逆向分析」面板 ──IPC──▶ 主进程 reverse 服务 ──调度核心 process 执行体──▶ 子进程：node scripts/rea.mjs mcp（常驻 MCP stdio 服务）
      ▲                                                                              │
      └── 内置 AI ◀── 现有 MCP 客户端（stdio）接上这个子进程，像接任何 MCP 服务 ◀──────┘
```

与深度科研的关键差异：Chain-Centric 是**一次性 CLI**（session 执行体，跑完即止）；**REA 是常驻 MCP 服务**，所以：
- 用**现有 MCP 管理 + MCP 客户端**接入，不在 sikeoop 进程里加载它的代码。
- 调度核心用 **`process` 执行体**（上批给 Quarto 加的那种）管这个常驻子进程：出现在调度台、可看状态、可取消（结束进程树）、有空闲超时。
- 内置 AI、以及经 sikeoop 中转的 Claude Code / Codex，都把它当一组 MCP 工具来调。
- 环境变量显式注入（`XDG_CONFIG_HOME` 指向沙箱配置、`REA_*` 指向用户自备的外部引擎、`REA_LOG_LEVEL` 等），显式值优先于它读到的全局配置——沿用深度科研与 `cli-agents/bundled.ts` 的做法。
- **不调 `rea setup`、不改用户任何 agent 配置**；配置目录指到 `userData` 下的沙箱目录。

## 3. 打包方式对比

| 维度 | A. vendor 进 `resources/`（像 chain-centric 带源码） | B. 首次使用按需装到 `userData/tools/rea/`（像 Quarto 托管安装 / chain-centric 的 venv） |
|---|---|---|
| 大小 | 大。不只 7.7MB 的包，还要带 `node_modules`（含 playwright-core 等）与**各平台原生模块**（`node-pty`、它自带的 `rea-windows-x64.node`）——会重演 mac-natives/win-natives 的按架构补包问题，每个安装包可能 +100MB 以上 | 小。安装包几乎不增重 |
| 原生模块 | 要为每个平台/架构预置，复杂 | npm 按本机环境自行解析，省掉按架构塞包 |
| 更新 | 更新 rea 要重打包 sikeoop | rea 可独立更新（改 pin 的版本号即可） |
| 首次使用 | 离线可用、版本锁定 | 需联网 + 本机有兼容 Node/npm，约 1–2 分钟 |
| 许可 | 保留 `LICENSE` 与署名 | 同样保留 |

**建议 B（按需装到 userData）**，理由：rea 体积与原生依赖大、本就需要本机 Node 运行时，按需安装能避开按架构塞原生包，并能独立更新——与上批 Quarto 托管安装、深度科研 venv 的模式一致。具体：
- pin 版本 `rea-agents@6.4.0`（或后续选定版），装进 `userData/tools/rea/`；安装前征得同意、显示进度、可取消。
- 校验 npm provenance / 完整性（SLSA attestation + registry 签名），不跑它的生命周期脚本（`--ignore-scripts`；本就没有 install 钩子）。
- **用户自己全局装的 `rea` 优先**（像 Quarto：检测到用户自备就用用户的，不重复装）。

## 4. 界面：「逆向分析」面板

侧栏（建议放「AI 协作」堆或独立入口）一个面板：
1. 选目标：本地文件 / 已安装应用 / APK / IPA / .NET 程序集 / 固件镜像 / 已打开的网页或 Electron 运行时。
2. 选分析类型（静态为主）：看结构总览、反编译某函数、比较两个版本、抽取某特性的实现等。
3. 看结果与**证据**：每条结论标明「观察 / 推断 / 未知」，带 Evidence ID、覆盖边界与局限（REA 的既有产物结构）。
4. 外部引擎缺失时给**安装指引**（按需、不打包 Ghidra/IDA/Hopper/JADX 等，只告诉用户怎么装并指 `REA_*` 到它）。
5. 「运行时捕获」单独分区，默认折叠、默认关（见第 5 节）。

实际工具调用仍走内置 AI + MCP；面板是把常见入口做成按钮，少让用户手搓。

## 5. 安全边界

- **运行时/捕获类工具默认关、每次审批**：`capture_*`、`observe_*`、`trace_native_ui_action` 等会执行或附加到目标程序（以用户权限），风险最高。默认禁用；用户显式开启某次捕获时，用审批卡列明「将运行/附加到哪个目标程序」，一次一授权。静态只读类工具正常走现有 MCP 审批即可。
- **只分析用户自己选的目标**：不替用户挑目标（SKILL 本身也要求「Never choose an example app on the user's behalf」）。
- **首次使用显示合法使用与授权声明**：逆向分析只针对用户有权分析的目标；同一项目第一次用时单独确认（同 Jev / 深度科研的首用同意）。
- **结果只当资料**：REA 产出的文字、反编译内容一律当数据，不从其中解析/执行命令。
- **配置与网络隔离**：`XDG_CONFIG_HOME` 指向 userData 沙箱，不碰用户全局 `~/.config/rea`；不调 setup、不改 agent 配置；安装时 `--ignore-scripts`。
- **进程与超时**：调度核心任务设空闲超时；取消时结束整个进程树。
- 不打包、不自动安装 Ghidra/IDA/Hopper 等重型外部引擎，只给安装指引。

### 分批建议

- **第一批（能用）**：按需安装 + 校验 + 拉起 MCP 子进程 + 接进现有 MCP 客户端 + 调度核心 process 执行体 + 一个最小面板（只静态只读工具）。先只对内置 AI 开放。
- **第二批（外部引擎）**：Ghidra/IDA/Hopper/JADX 等的检测与安装指引、`REA_*` 配置界面。
- **第三批（运行时捕获）**：capture/observe 类，默认关 + 每次审批 + 合法声明。
- **第四批（中转开放）**：经 sikeoop MCP 把 rea 工具开放给 Claude Code / Codex，同样走审批。
