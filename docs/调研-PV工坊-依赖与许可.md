# 调研：PV 工坊依赖与许可

访问日期：2026-10-12（以下来源均为本次联网检索或抓取的结果）

## 结论与建议

- **ffmpeg LGPL 构建**：只找到 Windows x64 的可信来源（BtbN LGPL ZIP）。macOS（arm64/x64）没有找到官方来源的 LGPL 预编译包；Linux x64 在 BtbN 页面有 Linux 构建，但没有确认其中 LGPL 变体的具体文件名。evermeet.cx 能访问到的是 macOS 的 ffmpeg 目录，但 HTTPS 跳转到 deolaha.ca 后返回 404，没有核对到 LGPL 声明和校验值。**建议**：macOS 和 Linux 先只探测系统已安装的 ffmpeg，找不到就提示用户自行安装，等找到可信来源再开放下载。
- **Remotion 许可**：官方 FAQ 明确允许"生成 Remotion 代码并渲染的服务"。这类工具要按 Remotion 的 Automators 计费（render 计费），除非公司人数在 3 人以内（免费许可）。**建议**：先确认公司人数，人数超过 3 人就需要购买 Company License，并以官方价格页为准；价格页未能抓取到具体数字，需要人工确认。
- **Mixkit 音乐与音效**：官方摘要页写明音乐可用于 YouTube、播客和线上广告，无需署名（署名"appreciated but not required"），禁止用于 CD、DVD、电子游戏和电视/广播。完整许可页没有抓取成功。**建议**：宣传片可以用，但不要用于游戏或广播；下载时确认每个素材对应的许可类型，并读 mixkit.co/license/ 原文。

## 一、ffmpeg 的 LGPL 构建

### 1. 页面原文写的

- BtbN/FFmpeg-Builds 的仓库说明：静态 Windows (x86_64) 与 Linux (x86_64) 构建，还列出了 linuxarm64 目标。自动构建仅包括 win(arm)64 与 linux(arm)64。仓库中不包含 macOS 构建。（来源：https://github.com/BtbN/FFmpeg-Builds/releases/tag/latest 的检索摘要）
- BtbN 发布页列出了 LGPL 与 GPL 两种变体，其中有 `ffmpeg-master-latest-win64-lgpl.zip` 这类文件名，LGPL 静态版是官方发布项之一。（来源：同上）
- 第三方 winstall.app 页面描述 LGPL 静态版基于 8.0 release 分支，并除去 GPL-only 依赖。这是第三方描述，不是官方原文。（来源：https://winstall.app/apps/BtbN.FFmpeg.LGPL.8.0）
- evermeet.cx/pub/ffmpeg/ 的 macOS 构建来源：某项目 README 写明 macOS x64 从 evermeet.cx 下载、arm64 从 osxexperts.net 下载。（来源：检索摘要，未直接打开该 README）
- 直接访问 https://evermeet.cx/pub/ffmpeg/ 返回 302 跳转到 https://deolaha.ca/pub/ffmpeg/，该地址返回 HTTP 404，没有读到文件列表、校验文件和许可说明。

### 2. 你的推断（未经验证）

- evermeet 与 osxexperts 的构建是否为 LGPL 构建，未经核实，不能直接当作 LGPL。
- 任何第三方镜像提供的 SHA-256 都不能作为校验依据。

### 3. 没有查到的

- macOS arm64/x64 的可信 LGPL 预编译源：**没有找到合格来源**。
- Linux x64 的 LGPL 变体文件名与校验文件：**未确认**。
- 官方发布的 SHA-256 或签名文件：**未找到**（BtbN 有 release 资产的 digest，但仅限其已有平台）。
- LGPL 构建中可用的 H.264 / AAC 编码器：本次没有查到明确列表。libx264 属于 GPL，所以 LGPL 构建通常没有 H.264 软件编码器，需要用硬件编码器（如 h264_videotoolbox）或 FFmpeg 原生 AAC 编码器（aac）。这是基于通用知识的推断，请用实际构建的 `ffmpeg -encoders` 核对。

## 二、Remotion 许可

### 1. 页面原文写的

- 免费许可：个人，或不超过 3 人的组织/团队，或非营利组织。（来源：https://www.remotion.dev/docs/license/faq）
- FAQ 原文："Yes, it is allowed to build a service that generates Remotion code using artificial intelligence and renders it."（允许构建一个用 AI 生成 Remotion 代码并渲染的服务）
- FAQ 原文："Your customers can be other companies and they don't need to have a Company License."（客户不需要单独购买许可）
- FAQ 原文："Allowing end-users to edit the Remotion code is also permitted if the code was initially generated by your service."（如果代码由你的服务生成，允许终端用户编辑）
- FAQ 说明：调用渲染 API 或命令的属于 "automation"，prompt-to-video 类工具归入 "Remotion for Automators"。（来源：同上）
- 不允许：让用户上传自己的 Remotion 代码到你的服务器渲染。（来源：同上）
- 允许：让用户基于你的模板渲染自己的个性化视频。（来源：同上）
- 价格（来自检索摘要，需以官方价格页为准）：Creators 每座位 $25/月；Automators 每次渲染 $0.01，最低 $100/月；Enterprise 起价 $500/月。（来源：https://www.remotion.dev/docs/license/pricing 的检索摘要。直接抓取该页时只得到占位内容，没有读到价格。）
- 检索摘要提到 Remotion 5.0 许可会有变化，但未查到具体内容。

### 2. 你的推断（未经验证）

- 桌面应用替用户生成 Remotion 工程并调用 CLI 渲染，依 FAQ 应归为 Automators 用法，除非应用开发方公司人数在 3 人以内。
- 如果渲染的是用户自己生成的工程，而不是用户上传的代码，FAQ 的禁止项不适用；但仍需确认是否属于 "automation"。

### 3. 没有查到的

- 价格页的完整正文与最新价格：**未抓到**，只有检索摘要。
- 许可 FAQ 中对"桌面应用本地调用 CLI"这一场景的明确说明：**未找到**，建议发邮件到 hi@remotion.dev 确认。
