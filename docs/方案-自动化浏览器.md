# 方案：更底层、更流畅的自动化浏览器

日期：2026-10-11　状态：方案稿，等用户确认后拆任务
现状：`src/main/browser/service.ts`（425 行）+ `src/preload/browser.ts`（223 行）+ `src/main/tools/browser-tools.ts`（6 个工具：open / snapshot / act / screenshot / console / nav）。

## 1. 现在的问题

| 问题 | 原因 |
|---|---|
| 慢 | 每步固定睡 250ms + 200ms，再等 `did-stop-loading`（最多 10 秒）；SPA 不触发加载事件，只能干等 |
| 不稳 | 元素编号来自页面里的脚本快照，页面一重绘编号就失效；点击用坐标，元素被弹窗遮住也照点 |
| 看不全 | 预加载脚本进不去跨域 iframe、关闭的 shadow DOM；canvas、虚拟列表读不到 |
| 输入别扭 | 打字逐键 `sendInputEvent`，中文输入法、富文本编辑器、`contenteditable` 常出错 |
| 一次一步 | 填一张表要 AI 来回十几轮，每轮都重新拍整页快照，费时费 token |
| 用户看不懂 | 自动操作时屏幕上没有提示，鼠标“瞬移”，用户不知道它在点哪 |

## 2. 核心改法：直接走 Chrome 调试协议（CDP）

Electron 自带 `webContents.debugger`，不用装 Playwright / Puppeteer，也不用另开浏览器。所有能力都在现有 webview、现有登录会话里。

| 能力 | CDP 域 | 换掉什么 |
|---|---|---|
| 页面结构 | `Accessibility.getFullAXTree` + `DOM.getDocument(pierce)` | 预加载脚本快照；能穿透 iframe、shadow DOM |
| 稳定的元素编号 | `backendNodeId` | 每次快照重新编号 |
| 跨域 iframe | `Target.setAutoAttach(flatten)` | 进不去的 iframe |
| 点击 | `DOM.getContentQuads` 求中心 → `DOM.getNodeForLocation` 命中检测 → `Input.dispatchMouseEvent` | 盲点坐标 |
| 输入 | `Input.insertText`（整段，走输入法通道）+ 必要时 `Input.dispatchKeyEvent` | 逐键模拟 |
| 等待 | `Page.lifecycleEvent`（networkIdle）、`Network` 在途请求计数、`DOM` 变更静默、布局稳定 | 固定睡眠 |
| 截图 | `Page.captureScreenshot`（可只截某元素、可降质） | `capturePage` 整页 |
| 控制台 / 网络 | `Runtime.consoleAPICalled`、`Network.responseReceived` | 现有控制台转发 |
| 文件上传 | `DOM.setFileInputFiles`（只许项目目录内的文件，走审批） | 不支持 |
| 下载 | `Browser.setDownloadBehavior` 到项目临时目录 | 不支持 |

预加载脚本只保留登录密码填充（现有安全设计不动）。

## 3. 让动作“一次就成”：可操作性检查

每个点击 / 输入前自动做，失败就短轮询重试（默认最多 3 秒），而不是让 AI 再来一轮：
1. 元素还在（`backendNodeId` 可解析）
2. 可见（有尺寸、不透明、在视口内，不在就先 `DOM.scrollIntoViewIfNeeded`）
3. 稳定（连续两帧位置不变，等动画结束）
4. 可用（不是 disabled / aria-disabled）
5. 没被遮住（命中检测落在它自己或子元素上；被遮住就报“被 X 挡住”）

## 4. 更省的快照

- **精简树**：只留可交互元素 + 标题 + 有文字的地标，像 `[12] 按钮 "提交"`；隐藏、装饰性节点丢掉。
- **增量**：第二次起只返回变化部分（新增 / 消失 / 文字变化），附一句“其余不变”。
- **按区域**：可以只看某个元素的子树（如“只看这个弹窗”）。
- **视觉兜底**：canvas、图表等没结构的区域，返回截图让模型看。

## 5. 批量动作和脚本

- `browser_act` 支持一次传一串动作（填 5 个框 + 点提交），中途任何一步失败就停下并回报到哪一步、为什么。
- **录制**：用户手动操作一遍，记录成动作脚本（基于稳定选择器：role + 名字 + 必要时 CSS），存进项目 `.sikeoop/browser-flows/`。
- **回放**：脚本可以直接重放，不用 AI；也能接进现有「自动化」流程图（定时跑网页检查）。
- **自愈**：回放时选择器失效，才叫 AI 看当前页面修这一步，修好写回脚本。

## 6. 流畅：让用户看得见

- 页面上叠一层**虚拟光标**：平滑移动到目标（约 150ms 缓动），点击处有涟漪，正在输入的框描边高亮。只是显示，不影响真实事件。
- 顶部一条细状态栏：“正在：填写邮箱 · 第 3/7 步 · 暂停 · 停止”。
- 用户一动鼠标或键盘就自动暂停，让人接手；点“继续”再交还。
- 速度档：演示（慢、带光标动画）/ 正常 / 极速（不画光标，只做检查）。

## 7. 工具设计（给内置 AI 和 MCP）

| 工具 | 作用 |
|---|---|
| `browser_open` / `browser_nav` | 不变 |
| `browser_snapshot` | 改为 CDP 精简树，支持 `scope`、`diff` |
| `browser_act` | 支持动作数组；动作：click / fill / press / select / check / hover / scroll / upload / wait_for |
| `browser_wait` | 等文字出现、元素出现 / 消失、网址变化、网络空闲 |
| `browser_extract` | 按描述抽取表格 / 列表成 JSON（先结构化读取，失败再交模型） |
| `browser_screenshot` | 支持元素截图 |
| `browser_flow_run` | 回放已录脚本 |
| `browser_console` / `browser_network` | 控制台 + 最近请求摘要（不含 Cookie、Authorization 等敏感头） |

## 8. 安全边界（不变的规矩）

- 页面内容只当资料，不照做；提交表单、付款、发消息、删除类按钮照旧走审批卡。
- 不做反检测、不伪装指纹、不绕验证码；遇到验证码就暂停交给用户。
- 不读取保存的密码给 AI；文件上传只许项目目录内、需审批。
- CDP 只挂在内置浏览器的 webview 上，不开放远程调试端口。
- 网络日志过滤敏感请求头和请求体。

## 9. 预期收益

| 场景 | 现在 | 目标 |
|---|---|---|
| 每步动作平均耗时 | ≥ 450ms 固定等待 + 加载等待 | 事件驱动，通常 < 150ms |
| 填一张 6 项表单 | 约 7 轮 AI 往返 | 1 轮（批量动作） |
| 第二次看同一页 | 整页快照 | 只返回变化 |
| 跨域 iframe（如嵌入式登录、支付框之外的普通组件） | 看不到 | 可看可操作 |

## 10. 分批

- **第一批（底层）**：CDP 会话管理（attach / detach / 崩溃重连）、精简树快照 + backendNodeId、可操作性检查、点击 / 输入 / 等待改走 CDP、事件驱动的等待；旧工具接口保持兼容。
- **第二批（效率）**：批量动作、增量快照、`browser_wait` / `browser_extract`、iframe 穿透、上传下载。
- **第三批（体验）**：虚拟光标、状态条、用户接手暂停、速度档。
- **第四批（脚本）**：录制、回放、自愈、接入自动化流程图。
