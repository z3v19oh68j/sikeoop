# PV 工坊 · 验收清单

日期：2026-10-12　依据：`docs/方案-PV工坊.md`、第一批和第二批任务书、各份汇报，以及当前代码（只读，未启动应用）。
用法：照着下面的步骤在应用里点一遍。每条写了「应该看到什么」；如果不对，「可能的原因」指向代码文件，方便交给对应的人。

> 说明：本清单是按代码写的，**没有在真实应用里逐条点过**。末尾第 6 节列出了还没人实际验证的环节。

## 1. 准备工作

### 1.1 怎么进到 PV 工坊

- **只在开发版显示。** 要用 `npm run dev` 启动（脚本见 `sweet-code-desktop/package.json`）。打包好的正式版里看不到，这是代码里的开关：`sweet-code-desktop/src/renderer/src/unfinished.ts:3`（`SHOW_UNFINISHED = import.meta.env.DEV`）。
- **入口一：左侧栏。** 在「项目」分组里找到「PV 工坊」（图标是一个播放三角）。位置在 `sweet-code-desktop/src/renderer/src/components/Sidebar.tsx:98`。
- **入口二：命令面板。** 按命令面板快捷键，输入「PV」「pv」「宣传片」或「视频」，选「PV 工坊」。位置在 `sweet-code-desktop/src/renderer/src/App.tsx:488`。
- **前提：先打开一个项目（工作区）。** 没打开时页面上方会显示「先打开一个项目，片子会放在项目的 pv/ 文件夹里」，「新建片子」按钮是灰的。
- 片子的文件都存在 `<你的项目>/pv/<片子编号>/` 下面，包括 `project.json`、`brief.md`、`script.md`、`storyboard.json`、`assets/`、`remotion/`、`out/`。

### 1.2 需要先装什么

| 东西 | 什么时候需要 | 怎么装 | 代码依据 |
|---|---|---|---|
| **ffmpeg（macOS）** | 分析节拍、出预览片 | 在终端运行 `brew install ffmpeg`。应用**不会**替你下载。 | 应用只在 `PATH`、`/opt/homebrew/bin`、`/usr/local/bin`、`/usr/bin` 里找 ffmpeg：`sweet-code-desktop/src/main/pv/ffmpeg.ts:11-19`。macOS 下载功能未启用：`ffmpeg.ts:50` |
| **ffmpeg（Windows）** | 同上 | 应用会按需下载（需要你在弹窗里点同意，校验 SHA-256）。 | `ffmpeg.ts:49-54`；后端汇报第 1 项 |
| **Remotion 依赖** | 出预览片 | 在 `<项目>/pv/<片子编号>/remotion/` 目录里自己运行 `npm install`。应用**不会**自动安装。 | `sweet-code-desktop/src/main/pv/service.ts:162-163`（找不到 `@remotion/cli` 时会报「请先在 PV 项目 remotion 目录安装依赖」） |
| **模型服务商** | 「让 AI 写」（需求、脚本、分镜、合成） | 在设置里配好一个可用的模型服务商。 | `sweet-code-desktop/src/main/index.ts:1506` 使用当前「子任务」模型路由。没配好时的具体报错文字：**未在代码中确认** |

> 注意：ffmpeg 的状态在页面打开时读取一次（`sweet-code-desktop/src/renderer/src/components/pv/PvScreen.tsx:31-35`）。装好 ffmpeg 后，**切到别的页签再切回来**，页面才会重新检查。

## 2. 第一批：需求 → 分镜 → 合成 → 出片

### 2.1 新建片子

1. 点页面右上角「新建片子」。
2. 应该看到：弹窗，有「片名」「类型（产品宣传片 / 音乐 PV）」「画面比例（16:9 横屏 / 9:16 竖屏 / 1:1 方形）」「时长（秒，默认 30）」。「创建」在片名为空时是灰的。
3. 填「比如 sikeoop 30 秒宣传片」，点「创建」。
4. 应该看到：弹窗关闭，右上角片子下拉框里出现新片子，左侧七步都是「未开始」。在 `pv/` 下会生成一个新文件夹，里面有 `assets/`、`out/`、`remotion/`。
5. 不对的话：创建失败会在页面上显示红字。参数校验在 `sweet-code-desktop/src/main/pv/store.ts:73`；弹窗在 `sweet-code-desktop/src/renderer/src/components/pv/PvScreen.tsx:83-104`。

### 2.2 需求（brief）

1. 左侧点「1 需求」。
2. 应该看到：一个文本框，空的时候提示「这条片子给谁看、想让人记住什么……也可以先点『让 AI 写』」。下方写着 `pv/<编号>/brief.md · Markdown`。
3. 随便输入一句，点「保存」。应该看到按钮变成「已保存」。切到别的步骤再回来，内容还在。
4. 点右上角「让 AI 写」。应该看到：步骤状态变「进行中」，几十秒内变「完成」，文本框内容被替换成 AI 写的内容。
5. 不对的话：保存失败看 `PvScreen.tsx:238`；AI 写失败时状态变「出错」，红字显示原因（原因来自 `service.ts:146`）。

### 2.3 脚本（script）

1. 左侧点「2 脚本」。
2. 应该看到：和需求一样的文本框，提示「旁白和字幕，按时间写。」
3. 操作同 2.2：保存，然后点「让 AI 写」。
4. 不对的话：同 2.2。脚本的提示词会带上经验包里对应「脚本」步的条目，见 2.9。

### 2.4 分镜表：编辑、排序、总时长

1. 左侧点「3 分镜」。
2. 应该看到：顶部一行「总时长 X 秒 / 目标 Y 秒」。两个数相等时是绿色，不相等时是橙色警告色。下面是镜头卡片，每张有序号、「秒」「景别」「运镜」「来源」「画面」「字幕」「转场」。
3. **改时长**：把某个镜头的「秒」改成别的数字。应该看到：顶部的总时长立刻变化，颜色随之变（相等为绿，不等为橙）。「保存分镜」按钮从「已保存」变成可点。
4. 点「保存分镜」，应该看到按钮变回「已保存」。刷新或切换片子再回来，改动还在。
5. **拖动排序**：按住左边的「⋮⋮」把手拖到另一个镜头上松开。应该看到镜头顺序变了，序号重新排。
6. **上移 / 下移**：点镜头右侧的上下箭头。第一个镜头的「上移」和最后一个的「下移」应是灰的。
7. **加镜头**：点「加镜头」，应该多出一张默认 3 秒、「代码画面」的卡片。
8. **删除镜头**：点垃圾桶图标，镜头消失。
9. 不对的话：
   - 总时长不更新 → `PvScreen.tsx:253`（总时长计算）。
   - 拖动没反应 → `PvScreen.tsx:267`（拖放事件）。
   - 保存后丢了 → 后端保存在 `sweet-code-desktop/src/main/pv/store.ts:84`，分镜格式校验在 `store.ts:19-44`（例如时长必须大于 0 且不超过 3600 秒，镜头 ID 不能重复）。

### 2.5 让 AI 写分镜

1. 在「3 分镜」步，点右上角「让 AI 写」（已有分镜时按钮叫「让 AI 重写」）。
2. 应该看到：状态变「进行中」，完成后镜头卡片被替换；总时长应接近项目设定的时长（提示词里要求「总时长与项目一致」，见 `service.ts:116`）。
3. 不对的话：AI 返回的内容不是合法分镜时，状态变「出错」，红字写着原因，例如「分镜不是有效 JSON」（`store.ts:25`）。这时分镜文件**不会**被改。

### 2.6 经验包侧栏

1. 在任一步骤的编辑区下方，找到经验包折叠区。
2. 应该看到：按包分组、可折叠的列表（包名、条目标题）。有「这一步 N 条」的包默认展开，只用于其他步骤的包默认折叠。
3. 切换到不同步骤，展开的内容应随之变化。例如切到「脚本」，应该能看到和脚本相关的条目。
4. 应该只读：不能编辑经验包内容。
5. 不对的话：条目是按步骤筛选的，筛选在 `sweet-code-desktop/src/main/pv/packs.ts:15-17`；界面在 `sweet-code-desktop/src/renderer/src/components/pv/PackPanel.tsx`。如果看到「还没读到经验包」，检查 `resources/pv-packs/` 目录下是否有 JSON 文件。

### 2.7 合成（compose）

1. 先确保「3 分镜」里**至少有一个镜头**。没有分镜，合成会报「请先完成分镜」（`service.ts:129`）。
2. 左侧点「6 合成」，点「让 AI 写 Remotion 组件」。
3. 应该看到：状态变「进行中」，完成后变「完成」。在 `<项目>/pv/<编号>/remotion/` 下出现 `package.json`、`src/index.tsx`、`src/storyboard.json`、`src/media.json`、`README.md`。`src/storyboard.json` 的内容和当前分镜一致。
4. 如果有 ffmpeg 外的新素材（图片或视频镜头），`remotion/public/assets/` 下应有对应文件的复制（`service.ts:92-103`）。
5. 不对的话：
   - 报「编程代理返回非法文件」或「未返回完整 src/index.tsx」：AI 输出格式不对，`sweet-code-desktop/src/main/index.ts:17-30`（对返回文件的校验）。
   - 合成不会安装依赖，这是设计如此（`README.md` 里也写了）。

### 2.8 出片与预览（ffmpeg + Remotion）

**情况 A：ffmpeg 没装好**

1. 左侧点「7 出片」。
2. 应该看到：「出预览片」按钮是灰的，旁边写「还没有 ffmpeg」，还有「怎么装？」链接。
3. 点「怎么装？」。应该看到一段说明，写的是会从官方镜像下载约 80 MB、校验 SHA-256、点同意才开始，还有「下载 ffmpeg」按钮。
4. **注意：** 在 macOS 上这段说明和按钮**不适用**。见第 4 节「没装 ffmpeg」。

**情况 B：ffmpeg 已装好（brew 安装后，切走再切回来）**

1. 点「出预览片」。
2. 应该看到：按钮变「进行中」，渲染完成后右侧「预览」区出现播放器，下面显示 `out/preview-<随机>.mp4` 的路径。
3. 播放器能播放，能拖动进度条（支持部分内容请求）。
4. 在 `<项目>/pv/<编号>/out/` 下应该看到：`preview-*.mp4`、同名 `.srt` 字幕文件、同名 `.jpg` 封面。
5. 不对的话：
   - 「请先在 PV 项目 remotion 目录安装依赖」：去 `remotion/` 目录 `npm install`（见 1.2）。
   - 「渲染失败：…」后面跟着 Remotion 的输出日志，照日志看。渲染入口在 `service.ts:160-178`。
   - 预览区一直显示「还没出片」但文件其实生成了：播放器地址由 `pvPreviewUrl` 给出，协议在 `sweet-code-desktop/src/main/pv/protocol.ts:18-21`。
   - 播放器一片黑或不动：媒体协议在 `index.ts:213` 和 `index.ts:2546` 注册。

### 2.9 步骤状态、进度与取消

1. 左侧每一步右边有状态标签：「未开始」（灰）、「进行中」（蓝）、「完成」（绿）、「出错」（红）。
2. 点任一「让 AI 写」后，该步骤应立刻变「进行中」，并且出现「取消正在跑的步骤」按钮。
3. 点「取消正在跑的步骤」。应该看到：该步骤变成「出错」，红字写「已取消」（取消在代码里会以出错的形式报告：`service.ts:146`）。
4. 不对的话：状态不更新 → 进度事件 `pv:progress` 的订阅在 `PvScreen.tsx:36-39`。

## 3. 第二批：素材、卡点、配乐、带配乐出片

### 3.1 导入素材

1. 左侧点「5 素材」。
2. 点「导入文件」。应该看到：系统的文件选择框弹出，只显示图片、视频、音频类文件（过滤器在 `sweet-code-desktop/src/main/index.ts:2153`）。
3. 选 2 张图片和 1 段音乐（例如 `.mp3`），点「打开」。
4. 应该看到：列表里出现 3 条，每条有缩略图（图片、视频）或「♪」（音频），下方写类型和大小（视频和音频如果能读到时长也会显示）。导入的文件在 `<项目>/pv/<编号>/assets/` 里，**原文件不会被改动**。
5. 导入时按钮会变「导入中…」。
6. 不对的话：
   - 文件名被改了（例如 `a-2.png`）：这是重名处理，正常。规则在 `sweet-code-desktop/src/main/pv/assets.ts:61-88`。
   - 缩略图显示「没预览」：常见于 `.mkv`、`.avi` 等 Chromium 不能直接播放的格式，代码中没有转码。
   - 「没导进来：…」：看具体文字。大于 512 MB 会被拒绝（`media.ts:4`）。

### 3.2 删除素材

1. 点某个素材右边的垃圾桶图标。
2. 应该看到：该素材从列表消失，`assets/` 里的文件也被删除。
3. **没有二次确认**，也不会提示哪些镜头在用它（任务书没要求，第二批前端汇报第 53 行也写了）。
4. 如果删的是当前配乐，列表里会提示「配乐已经……找不到了」（`AssetsStep.tsx:46-47`），节拍数据也会被清掉（`service.ts:48-54`）。
5. 不对的话：「没删掉：…」→ 看 `service.ts:51-57`。

### 3.3 设为配乐、取消配乐

1. 在一个音频素材上点「设为配乐」。
2. 应该看到：该行后面写「· 当前配乐」，按钮变成「取消配乐」。页面上方不再提示「还没选配乐」。
3. 对一个图片素材，**没有**「设为配乐」按钮（`AssetsStep.tsx:72-74`）。
4. 点「取消配乐」，应该看到「当前配乐」标记消失。
5. 换一首配乐后，「卡点」步的节拍数据会被判定为「给另一首歌算的」，需要重新分析（见 3.6）。
6. 不对的话：「配乐没设上：…」→ 看 `service.ts:58-67`（只接受音频文件）。

### 3.4 分镜里给镜头选素材

1. 在「3 分镜」步，把某个镜头的「来源」改成「文件素材」或「录屏」。
2. 应该看到：出现「用哪个素材」下拉框，列表里是已导入的图片和视频（**不含音频**，`StoryboardStep` 在 `PvScreen.tsx:280`）。
3. 选一个素材，保存分镜。应该看到「保存分镜」变成「已保存」，重新打开后选择还在。
4. 如果之前选的素材后来被删了，下拉框里会出现「xxx（找不到）」（`PvScreen.tsx:279`）。
5. 来源改成「代码画面」「AI 生成」时，这个下拉框消失。

### 3.5 检查素材

1. 在「5 素材」步，点右上角「检查素材」。
2. **情况 A：全部镜头都选好了素材。** 应该看到状态「完成」，报「素材检查通过」（后端文字，状态面板里能看到）。
3. **情况 B：有镜头没选素材。** 应该看到状态「出错」，红字写「素材检查没过：镜头缺少有效图片/视频素材：shot-2、shot-4」，并提示「到『分镜』步给这些镜头选好素材，再回来检查。」（`PvScreen.tsx:175-176`；镜头 ID 来自 `validateShotAssets`，`assets.ts:90-99`）。
4. 不对的话：检查逻辑在 `service.ts:125-126`。

### 3.6 分析节拍

1. 先按 3.3 设好配乐。左侧点「4 卡点」。
2. 应该看到：页面上有试听播放器（能听到配乐）。顶部按钮是「分析节拍」。提示文字「节拍是电脑估算的，不一定每首歌都准，定稿前请自己听一遍切点。」（`BeatsStep.tsx:87`）。
3. 点「分析节拍」。应该看到：按钮变「分析中…」，提示「正在分析节拍，一般几秒钟…」，完成后出现：
   - 速度（BPM）
   - 第一拍位置（秒）
   - 把握程度（百分比；低于 60% 显示橙色，并提示「可能听错了速度（比如实际是一半或两倍）」）
   - 共多少拍 / 多少小节
4. 按钮变成「重新分析节拍」。
5. 不对的话：
   - 「未检测到可用起音」「可用起音太少」「节奏不够稳定」：配乐可能是静音、人声为主或太短，属于正常的拒绝；看 `sweet-code-desktop/src/main/pv/beats.ts:52、61、105`。
   - 「ffmpeg 未就绪，无法分析节拍」：去装 ffmpeg（见 1.2）。
   - 节拍数据在另一个文件里（`pv/<编号>/beats.json`）。

### 3.7 手改 BPM 和起拍偏移

1. 分析完成后，页面出现三个输入框：「每分钟拍数 BPM」「第一拍在第几秒」「每小节几拍」，下面有「应用修改」。
2. 把 BPM 改成 `128`，第一拍改成 `0.5`，点「应用修改」。
3. 应该看到：上方的速度和第一拍位置数字更新为你输入的值，拍数也随之变化。
4. 输入超出范围（BPM 小于 40 或大于 240，第一拍是负数，每小节不是 1 到 12 的整数）：「应用修改」是灰的，下面有一行橙字说明范围（`BeatsStep.tsx:113`）。
5. 注意：**分析之前没有这个表单**（`BeatsStep.tsx:96-97`）。要先分析一次。
6. 不对的话：「没改成：…」→ 看 `service.ts:76-87`、`beats.ts:14-18`（参数校验）。

### 3.8 试听

1. 在「4 卡点」步，页面上的播放器就是配乐。
2. 应该看到：可以播放、暂停、拖动进度。
3. 如果配乐文件找不到，显示「配乐加载不了，暂时没法试听」（`BeatsStep.tsx:89`）。
4. 不对的话：播放器地址来自 `pvAssetUrl`，协议在 `sweet-code-desktop/src/main/pv/protocol.ts:22-26`。

### 3.9 吸附到小节 / 拍：前后对比与确认

1. 分析完成后，在「4 卡点」步点「吸附到小节」（或「吸附到拍」）。
2. 应该看到：下方出现一张表，三列「镜头」「吸附前」「吸附后」，有变化的行是高亮的。最下面一行「合计」写着总时长和变化量（例如「+1.5 秒」）。
3. 下面一行提示：
   - 如果吸附后总长和目标时长一致：绿字「吸附后总长正好是目标的 30 秒」。
   - 如果不一致：橙字，写着比目标多或少几秒，并建议先保存再去分镜步加减镜头，或者换成另一种吸附单位。
   - 如果吸附后比配乐还长：橙字「片尾会有一段没有音乐」。
   - 如果每个镜头本来就卡在节拍上：灰字「不用改」，「确认并保存分镜」按钮是灰的。
4. **此时分镜文件还没有改动。** 去「3 分镜」步看一下，秒数应该还是原来的。
5. 点「算了」：表格消失，分镜不变。
6. 再点「吸附到小节」，然后点「确认并保存分镜」。应该看到：表格消失，出现绿字「分镜已更新」。去「3 分镜」步，各镜头秒数已变成整数个小节（或拍）。
7. 不对的话：

### 3.10 带配乐出片

1. 前提：已设配乐、已分析节拍（可选但推荐）、ffmpeg 已装、已做过「让 AI 写 Remotion 组件」、`remotion/` 里已 `npm install`。
2. 在「7 出片」步点「出预览片」。
3. 应该看到：预览区出现播放器，播放时能听到配乐。
4. 配乐从片子开头开始，片子结束时用 `-shortest` 截断（`service.ts:170-171`）。如果配乐比片子短，尾部会补静音（`apad`）。
5. 如果有图片或视频镜头，这些镜头在 Remotion 里是静音的（提示词里要求，`service.ts:132`），声音只来自配乐。
6. 不对的话：
   - 没有声音：检查 `out/` 里的 `preview-*.mp4` 是否有音轨（用播放器直接播放，或在终端用 ffprobe 看）。
   - 声音比画面长或短：看 `service.ts:170` 的参数。
