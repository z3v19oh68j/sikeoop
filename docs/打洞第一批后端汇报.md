## 新接口

### 共享类型

- `DispatchExecutorKind` 新增 `"agent"`，不复用 cli/process。
- `DispatchJob.progress?: DispatchProgress[]`：最近 100 条事件。
- `DispatchJob.result.files?: DispatchFiles`：`{ changed, created, deleted }`，路径相对第一 scope root；无法建立快照时不伪造空清单。
- `DispatchProgress`：`status | text | tool | permission | file`；ACP 批次当前产生前四类，本地文件以最终回执为准。
- `DispatchEvent` 新增 `{ type: "progress", jobId, progress }`。
- `AgentPermissionCard`：`id/jobId/sessionId/title/toolCall/options`。`options` 的 `optionId/name/kind` 和其他字段原样保留。
- `DispatchAgentInput`：`input` 必填，`readOnly/model/owns/timeoutMs/verify` 可选。
- 灵动岛 ask 状态增加 `options?`；`IslandApi.selectAgentPermission(id, optionId)` 为新增方法。

### SweetApi / IPC（新方法保持 required）

| 方法 | IPC |
| --- | --- |
| `dispatchAgentSubmit(input): Promise<{ jobId: string }>` | `dispatch:agent:submit` |
| `dispatchAgentPermission(id, optionId: string | null): Promise<void>` | `dispatch:agent:permission` |
| `onDispatchEvent(cb): () => void` | `dispatch:event` 订阅 |

现有 `dispatchView / onDispatchChanged / dispatchCancel` 继续使用。新提交及主窗口审批 IPC 检查 sender 等于主窗口 webContents，并拒绝生产版调用。

灵动岛新增 `island:agentPermission`；只接受岛窗口 sender、当前 ask 卡 id 和选项列表中的原始 optionId。

## 前端用法

1. 入口仅在 `SHOW_UNFINISHED` 下显示，调度台 kind 标签补 `agent: "外部 agent"`。主进程同时以 `!app.isPackaged` 限制入口。
2. 提交示例：

```ts
const { jobId } = await window.api.dispatchAgentSubmit({
  input: "检查当前项目，汇报发现，不修改文件",
  readOnly: true,
  model: "provider/model",
});
```

工作目录由主进程捕获当前项目，不接受 renderer 自选根目录。`model` 是外部工具自身的 provider/model；省略则沿用外部工具模型，不调用 sikeoop 模型路由。

3. 先显示启动卡（`acp-start:`）；其 `start/reject` 选项仅是 sikeoop 自己的启动审批。答复后才 spawn 外部进程。
4. `onDispatchEvent` 可显示即时进度；`onDispatchChanged` 已节流到约 250ms，`dispatchView` 可恢复当前任务/最近进度；避免同时将事件和快照重复追加。
5. `permission` 进度携带协议卡，显示 **原始 `option.name`**，点击回传 **原始 `option.optionId`**：

```ts
await window.api.dispatchAgentPermission(card.id, option.optionId);
// 主窗口主动放弃该权限请求：
await window.api.dispatchAgentPermission(card.id, null);
// 灵动岛页面：
window.island.selectAgentPermission(card.id, option.optionId);
```

拒绝选项同样以它自己的 optionId 回传；不得替换为布尔值或自己生成 allow/deny。旧灵动岛两按钮对协议卡的“批准”只打开主窗口、不自动授权；“拒绝”返回 cancelled。原始多选项需要前端本批渲染接入。

6. 取消调用现有 `dispatchCancel(jobId)`。连接器先发 `session/cancel`，默认 1.5 秒宽限，退出收尾对仍存活进程 SIGTERM，再宽限后 SIGKILL；任务完成回执前等待 child close。
7. 结束从 `job.result.files` 读取本地量出的改动清单，从 `checks` 显示验收结果。失败/取消的 agent 任务也尝试文件验收。不要从流式文字提取命令自动执行。
8. `dev-mock` 必须补：`dispatchAgentSubmit`、`dispatchAgentPermission`、`onDispatchEvent`。这些没有降级为 optional。

## 保守选择与未决事项

- 未提供只读参数时 **默认 readOnly=true**；显式 `false` 才使用可编辑模式。只读同时设置单次配置 `default_agent: "plan"` 并调用 `session/set_mode(modeId: "plan")`，不支持 plan 则失败，不回退 build。
- `OPENCODE_CONFIG_CONTENT` 仅单进程生效：可选模型、`permission: "ask"`、`plugin: []`。本连接器不注入旧 sikeoop 插件、不改全局配置；工具本来在磁盘上的其他全局配置如何合并由 opencode 自身决定，未实跑验证。
- 子进程环境是显式 OS/runtime 白名单；不继承 sikeoop/provider 的任意密钥变量，依赖 opencode 自己的登录。依赖环境变量认证的外部 provider 可能需要后续显式设计，但本批不默默透传全部环境。
- 命令固定 `opencode acp`，不经 shell，不传自动放行参数。Windows 若仅找到 `.cmd/.bat` 包装器，保守视为不可用，不自动改为 shell 执行；原生可执行文件路径尚未实测。
- 每任务一个 ACP child/session，executor ref 是 sikeoop 分配的会话标识；建 session 后权限/prompt/cancel 使用对方实际 sessionId。复用/续接/多 session 属于第三批，未实现。
- 权限超时/取消返回 ACP `cancelled`，不是推测一个拒绝 optionId；明确选择拒绝时仍返回 selected＋原始拒绝 id。无效 id 不会授权。
- 已知 edit/delete/move 权限检查结构化 locations 的真实路径及 owns；只读进一步拒绝 execute/switch_mode。执行命令及其他工具不是 OS 沙盒，获批命令仍可能越界，最终验收标注；不声称阻止所有任意 shell 写入。
- 验收沿用现有目录快照，忽略依赖/缓存/构建目录；并发同目录可能将别的任务改动计入 receipts，沿用现有提示。不是进程级写入审计，也不能看到 scope roots 外全部文件系统。
- `end_turn` 视为成功；`cancelled` 视为取消；token/turn 限额、refusal、未知 stopReason 视为失败，不把未完成当 done。
- `verify.typecheck` 是用户通过可信主窗口明确提交的验收命令，不来自外部输出；沿用现有 verifier 的任务前基线/任务后比较。其基线检查在外部进程启动卡之前运行，这是现有调度流程，不另改统一审批路由。
- `connect` 扩展定义、入站 MCP 四工具、交接包、全局审批统一路由不在第一批，未改。
- 本次用户明确要求所有后端项且共享接口仅新增，故补了必要 shared/preload 合同并在此完整交接；未修改 renderer 或既有审批决策流程。
- 手动 Electron/opencode 集成验收按用户限制 **未运行**；只对假的 ACP 进程验证生命周期。计划/权限细节参考方案第 11 节并对照 [ACP Tool Calls](https://agentclientprotocol.com/protocol/v1/tool-calls) 与 [ACP Prompt Turn](https://agentclientprotocol.com/protocol/v1/prompt-turn)；官方 session-setup 页本次抓取超时，未以其抓取结果作为证据。
