# 方案：论文工坊（借鉴 gpt_academic 的功能）

日期：2026-10-11　状态：草案，等用户确认第 6 节

## 1. 目标

在 sikeoop 里做一个「论文工坊」，和「深度科研」连成一条科研流程：

```
读论文（PDF / arXiv） → 翻译、总结 → 转成证据库 → 深度科研（Chain-Centric 对抗研判）
写论文 → 润色、纠错、互译
```

**借鉴的是功能设计**，参考 [gpt_academic](https://github.com/binary-husky/gpt_academic)（GPL-3.0）。sikeoop 自己实现，不打包、不 import 它的代码，也不把它的提示词原文写进 sikeoop。

## 2. 四个页签

### 2.1 读论文
- 输入：本地 PDF（项目里的或选文件）、arXiv 编号 / 链接（下载 PDF 前先说明会联网）。
- PDF 取文字：复用已有的 pdfjs-dist（`asarUnpack` 里已有）；按章节切块，公式和参考文献单独处理。
- 输出：
  - **结构化总结**：研究问题、方法、主要结论、数据与实验、局限、与相关工作的关系；
  - **全文翻译**：分块并行翻译（每块是调度核心里的一个 `model` 任务，便宜模型即可，可走「模型分工」的子任务模型），中英对照视图；
  - 导出 Markdown 到项目里（走审批卡）。

### 2.2 转证据库
- 从一篇或多篇论文抽取论点，直接生成 Chain-Centric 认的证据库格式：

  ```json
  [{ "ref": "arxiv:2401.12345", "title": "论文标题", "detail": "一句话结论（≤500 字）", "source": "论文工坊",
     "claims": [{ "title": "论点", "detail": "依据与数据（≤500 字）" }] }]
  ```
  （字段与截断规则以 `docs/深度科研-侦察报告.md` 第 6 节为准：title ≤200 字、detail ≤500 字。）
- 表格审阅：用户可增删改每条论点、看它出自原文哪一段（保存原文页码 / 段落定位）。
- 保存为项目里的 `research/<名字>.repository.json`；按钮「用它开始深度研判」→ 打开深度科研并预填证据库。
- 抽取出来的引用标明「来自论文原文」，和深度科研里「模型给的引用，未核实」区分开。

### 2.3 写作与润色
- 编辑区（或直接对编辑器里选中的段落）支持：学术润色（中 / 英）、语法与拼写纠错（**修改对照**，复用 `shared/diff.ts`）、中英互译、缩写 / 扩写、生成标题与摘要。
- 认识 LaTeX / Markdown：不破坏命令、公式、引用键。
- 改项目里的文件时走现有的审批卡与「撤销这一轮」。

### 2.4 arXiv 小助手
- 输入 arXiv 编号、链接或关键词：用 arXiv 官方 API 取标题、作者、摘要、分类、版本。
- 一键：翻译摘要、下载 PDF 到项目、送进「读论文」、加入证据库。
- 关键词检索结果列表（按相关度 / 时间），可多选批量处理。

## 3. 提示词

- **默认**：sikeoop 自己写的一套（中文为主，面向新手说明清楚每个按钮做什么）。
- **选配「gpt_academic 提示词包」**：设置里一个「导入」按钮，用户点击后由 sikeoop 从 gpt_academic 的 GitHub 仓库下载其提示词定义文件到本机，解析成可选预设；界面注明来源、作者、GPL-3.0 许可与仓库链接。**sikeoop 安装包与源码里不含这些提示词原文**，因此不涉及 GPL 分发义务。
- 用户也可以自己新增 / 修改预设（存在 userData，按项目可覆盖）。

## 4. 复用的现有能力

| 需要 | 现有 |
|---|---|
| PDF 取文字 | pdfjs-dist |
| 分块并行调用模型、排队、取消 | 调度核心 `model` 执行体（P4b） |
| 便宜模型做翻译 | 模型分工：子任务模型 |
| 改文件、撤销 | 审批卡 + checkpoints |
| 修改对照 | `shared/diff.ts` |
| 交给深度研判 | 深度科研 `ResearchRequest.repository = { kind: "file" }` |
| 联网 | 主进程 `net.fetch`（下载前先告知） |

## 7. 第二批（2026-10-11 用户确认加入；第一批验收完再做，交给空闲的终端 Claude Code）

借鉴 [The AI Scientist](https://github.com/SakanaAI/AI-Scientist) 的功能思路，**不接入、不打包它的代码，也不照搬其代码与提示词**（它需要 Linux + NVIDIA GPU + texlive-full，会执行 AI 写的代码，且许可为其自有的 AI Scientist Source Code License，含使用限制与强制 AI 披露条款）。

### 7.1 模拟审稿（写作页旁的新页签）
- 输入：论文（工坊里的 PaperDoc，或写作区文本 / 项目里的 .tex / .md）。
- 多个审稿人：用户选 2–5 个不同家的模型，各自按顶会格式审一遍：总分（1–10）、建议（接收 / 小修 / 大修 / 拒绝）、原创性 / 质量 / 清晰度 / 重要性分项、优点、缺点、给作者的问题、修改建议；每位审稿人可做 1–N 轮自我反思修正。每次模型调用是调度核心的 `model` 任务。
- 汇总：平均分与分歧、合并去重的缺点清单（标注几位审稿人提到）。
- 打通：每条缺点可一键送到「写作与润色」改对应段落；争议点可一键送到「深度科研」做对抗研判（生成问题 + 证据库）。

### 7.2 选题与新颖性检查（arXiv 小助手旁）
- 输入研究方向（可附上工坊里的论文作背景）→ 生成若干点子，每个给出：一句话、动机、可行的实验方案；按有趣度、可行性、新颖性打分。
- 新颖性检查：用 **OpenAlex**（免 Key）检索相近工作（可选 Semantic Scholar，用户自填 Key），列出最接近的论文并给出“已有人做过 / 部分重叠 / 未见”的判断与理由；检索前沿用 arXiv 的首次联网说明。
- 点子可一键：加入证据库草稿、开始深度研判、导出 Markdown。

### 7.3 AI 使用声明（写作页小工具）
- 按本项目里实际用过的功能（翻译、润色、纠错、模拟审稿、深度研判），生成一段放在方法 / 致谢中的 AI 使用说明（中 / 英）。

### 7.4 不做
- AI 自动做实验（改代码并运行）：风险与环境要求过高；如将来要做，放到云端沙盒，与 `docs/方案-云端接单.md` 一并考虑。

## 8. 第三批：引用与排版（2026-10-11 用户确认；第二批验收完再做，交给空闲的终端 Claude Code）

接入两个 **MIT 许可** 的外部工具，都由用户自行安装，sikeoop 只调用它们公开的接口，**不打包**：
- [Zotero Better BibTeX](https://github.com/retorquere/zotero-better-bibtex)（Zotero 8 插件；本机接口 `http://127.0.0.1:23119/better-bibtex/`：JSON-RPC 检索、CAYW 引用选择框、pull export 导出 .bib）
- [Quarto](https://github.com/quarto-dev/quarto-cli)（基于 Pandoc 的出版工具；自带 Typst，出 PDF 不需要 LaTeX；约 150MB，不进 sikeoop 安装包）

### 8.1 Zotero（Better BibTeX）
1. **插入引用**：写作页 / 编辑器一键调起 Zotero 的 CAYW 选择框，按当前文件格式插入 `[@key]`（Markdown / Quarto）或 `\cite{key}`（LaTeX）。
2. **参考文献同步**：项目 `references.bib` 从 Zotero 拉取更新（按项目选定的集合或按正文里用到的 key）。
3. **从 Zotero 导入论文**：检索文献库，把带 PDF 附件的条目导入论文工坊；转证据库时 `ref` 直接用 citekey，写作时可直接引用证据。
4. **检测与指引**：Zotero 未运行 / 未装 Better BibTeX / 版本不对时，给出大白话的安装与打开指引；只访问 `127.0.0.1`，不联外网。

### 8.2 Quarto
1. **一键排版**：把 `.qmd` / `.md` 渲染为 PDF（默认 Typst）/ Word / HTML，输出在项目内，可在 sikeoop 预览。每次渲染是调度核心任务，可取消，失败显示要点。
2. **论文模板**：新建论文（标题、作者、摘要、`references.bib`、CSL 引用格式）；默认中文 **GB/T 7714**、英文 **APA**，可改。CSL 文件来源与许可需在实现时核对（CSL 官方样式库为 CC BY-SA 3.0，随附时保留署名）。
3. **实时预览**：保存后自动重新渲染（`quarto preview` 或增量 render），在预览面板查看。
4. **检测与指引**：未装 Quarto 时给出安装指引；找到后显示版本。

### 8.3 约束
- 只在开发版显示，与第一、二批一致。
- 不改审批流程、模型路由、深度科研运行逻辑、发布、CLI 扩展、更新卡片。
- shared / preload 只新增；新逻辑配单元测试（CAYW / JSON-RPC 响应解析、引用格式化、.bib 合并、Quarto 命令组装与输出解析）。

## 9. 第四批：Quarto / Zotero 按需下载（2026-10-11 用户确认，交给空闲的终端 Claude Code）

不打进安装包（避免体积翻倍与随包分发 Pandoc（GPL-2.0）/ Zotero（AGPL-3.0）的义务），改为**用户点击后从官方来源下载**：

### 9.1 Quarto：托管安装
- 第一次需要排版时，若系统里找不到可用的 Quarto（≥1.4），提示“下载 Quarto（约 N MB，来自 GitHub quarto-dev/quarto-cli Releases，MIT；内含 Pandoc 等组件，各自许可见其包内说明）”，用户确认后下载。
- 按平台选资产（macOS `.tar.gz`、Windows `.zip`、Linux `.tar.gz`，x64 / arm64），用 GitHub Releases 提供的校验信息（API 的 `digest` 字段或发布的 checksums 文件）校验 SHA-256，校验不通过就删除并报错。
- 解压到 `userData/tools/quarto/<版本>/`，不需要管理员权限、不写系统目录；已存在则复用。可在设置里看到版本、更新到最新、删除。
- 优先级：用户自己装的 Quarto > sikeoop 托管的 Quarto。
- 下载走主进程 `net.fetch`，支持进度、取消、断点失败后重试；只访问 `api.github.com` 与 GitHub 的发布下载域名。

### 9.2 Zotero：一键引导安装
- Zotero 是完整桌面应用，**不静默安装、不内置**。检测到未安装时，「引用与排版」里给出两步：
  1. 「下载 Zotero」：从 zotero.org 官方下载地址取对应平台安装包，下载后用系统打开（`shell.openPath`），由用户完成安装。
  2. 「下载 Better BibTeX」：从 GitHub `retorquere/zotero-better-bibtex` Releases 取最新 `.xpi`（校验同上），保存后引导用户在 Zotero「工具 → 插件 → 从文件安装」装上；提供“打开所在文件夹”。
- 每一步都先说明来源、许可（Zotero AGPL-3.0、Better BibTeX MIT）、大小，用户点击才下载；之后重新检测连接状态。

### 9.3 约束
- 只在开发版显示；shared / preload 只新增；新逻辑配单元测试（平台资产选择、校验、解压路径安全、版本比较与优先级、下载状态机，网络部分用假 fetch）。
- 不改审批流程、模型路由、深度科研运行逻辑、发布、CLI 扩展、更新卡片、额度续写。
