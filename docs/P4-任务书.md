### P4a 跨项目 session（规格 M6，接线为主）

现有零件都写好了但没接线：`session/store.ts`（SessionStore，未被引用）、`session/scope.ts`（`checkScope` 无人调用）、`workspace-mode/launch.ts` 的 `buildSessionLaunch`（无人调用）、PeerBus 的 group 分支与 `onSessionEvent`（构造时没传）。

要做：
1. 新建 `src/main/session/service.ts`：实现 `CrossSessionApi` 的全部操作（list/get/create/addAgent/removeAgent/send/addRoot/end/openTerminal/stop），返回 `SessionResult`。
   - 成员 = PeerBus 里 `group = sessionId` 的 CLI 会话；每个成员对应一个调度核心 `CliExecutor`。
   - **@ 派活走调度核心**：`send` 里每个被 @ 的成员提交一个 job（origin `"session"`，scope.roots = session 的 roots）；成员之间的 send_to（PeerBus group 分支 → `onSessionEvent("send")`）也提交为 job，`parentId` = 发送方当前 job。**“同一时刻只一个 AI 发言”**用调度核心的队列实现（可在 service 内对同一 session 的 job 串行提交，或给 Dispatcher 加一个按 group 串行的选项——若改 scheduler.ts，须同时补测试并在汇报里写明）。
   - 预算用完 → 时间线插 `hopLimit` 事件（沿用类型名），用户在时间线发言即开新的根任务。
   - 越界：PreToolUse 由 `onSessionEvent("preToolUse")` 调 `checkScope` 判定，返回拒绝理由并插 `outOfScope` 事件；文件锁冲突插 `lockDenied`。
   - Stop → 成员回复写进时间线（`agent` 事件）。
   - 持久化用 SessionStore；重启后成员标 exited。
2. `src/main/index.ts`：构造 PeerBus 时传 `onSessionEvent`；注册 `session:*` IPC（见规格 IPC 表），推送 `session:event` / `session:changed`。**只改装配部分**。
3. `src/preload/index.ts`：把现在的 `session` 占位实现换成真实 IPC；删掉 `SESSION_NOT_READY`。
4. `src/renderer/src/dev-mock.ts`：`session` 占位换成能演示的内存 mock。
5. 渲染层 `components/crossSession.ts`：删掉复制的类型，改用 `@shared/types`；`sessionApi()` 只找 `window.sweet.session`。核对 tab id 规则（渲染层 `cs:<id>` 是面板标签，store 要求成员终端 `s:<id>:<agentId>`），在汇报里说明结论。入口目前只在 DEV 显示（`unfinished.ts` 的 `SHOW_UNFINISHED`），**保持不变**。
6. `docs/cross-session-spec.md`：按 D4 改写相关段落（MAX_HOPS → 预算；`window.api` → `window.sweet`）。

### P4b 群聊改用调度核心的 `model` 执行体

- 新建 `src/main/dispatch/model.ts`：`ModelExecutor`（kind `"model"`），包装一次流式模型调用。
- `src/main/group/service.ts`：每个成员发言 = 一个 job（origin `"user"`；一次用户发言的所有成员发言在同一棵树）。保持现有行为：被 @ 的按顺序发言，没 @ 全员发言，只读、不给工具，流式事件 `group:event` 不变，落盘格式不变。
- 去掉“全局只有一个 running”的限制，改为**同一个群串行、不同群可并行**。
- 停止：`stop()` 取消该群当前的根任务（级联）。

### P4c 回归面板接到调度核心

- preload 已有 13 个 `regress:*` 通道，主进程没有任何 handler（`unfinished.ts` 注释：src/main/regress is still empty）。类型在 `shared/types.ts` 的 `Regress*`；dev-mock 有完整的内存实现可作行为参考（含会话占用检查）。
