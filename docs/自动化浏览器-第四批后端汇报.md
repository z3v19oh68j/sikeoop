## 实现行为

### 第三批遗留

`browserAutomationPause()` 在 running 时主动暂停。原 `reason: string | null` 保留，新增可选 `pauseReason: "user" | "manual" | "approval" | "error"`，不破坏旧前端/mock 状态字面量。

- user：物理鼠标/键盘接手，reason 为「你接手了页面」。
- manual：调用暂停接口。
- approval：等待审批；批准/拒绝结束后仅自动恢复仍为 approval 的暂停。期间用户接手/主动暂停会覆盖为 user/manual，需用户继续。
- error：体验层安装/动画错误导致的暂停；执行失败终态也带 error。

继续清除 reason/pauseReason。暂停停在动作检查点，不撤回已经派发的动作；停止唤醒暂停并阻止后续动作。

### 录制与存储

监听用户手动 click/fill/select/check/press，加上主文档和 SPA 导航记录 navigate。开始时记当前 URL，记录期间拒绝自动化，自动化期间拒绝开始录制。开始/停止、切换项目、销毁/崩溃有清理边界；录制出错不保存半截脚本。

选择器优先记录 `role + name`；名称依次取 aria-label、aria-labelledby、关联 label、alt/title、按钮/链接文字、placeholder。附 CSS 和适用的精确文本兜底。回放以 CDP AX role/name 首先查找，必要时以 CSS/文本消歧，找不到才走兜底；多命中不猜第一个。`frameUrl` 限定所在文档，去除 credentials/query/hash 后匹配；不同 frame 仍多命中时拒绝。

连续同字段 fill/select/check 合并；键盘 Enter/Space 记录 press，避免把随后的浏览器自动激活 click 再录一次。只记录控制/导航键，不录普通字符按键。

输入策略：

- 默认 `values: "parameterize"`：普通 fill/select 不读取真实值，记录 `{valueN}`；N 为动作位置，每个不同字段拥有独立占位符。
- 显式 `values: "record"`：保存普通字段值。
- 密码类型和 current/new-password autocomplete：源头不读取 value、不录按键内容；只记 `password: true`、`description: "填写密码字段"`，主进程和磁盘写入再清除 text/key/files/未知字段。
- 导航 URL 的 username/password 删除；query 的所有值与整个 fragment 无论 values 模式均参数化为 `{urlN_queryM}` / `{urlN_hash}`，防 GET 密码或 token 间接落盘。路径与 query 名称保留；回放需要用户提供相应 URL 变量。

保存位置：**当前项目** `.sikeoop/browser-flows/<name>.json`，`version: 1`。名字允许 1–80 个 Unicode 字母/数字/空格/下划线/连字符，不接受扩展名、斜线、点路径或首尾空格。逐级检查目录，拒绝符号链接和非普通文件；读文件 O_NOFOLLOW，落盘临时文件 + 原子安装，默认权限 0600。录制同名不覆盖。最多 1000 步、1000 条历史、单文件 2 MB；未知版本拒绝。

### 回放与审批

`browser_flow_run(name, vars?)`、SweetApi 和流程图都进入同一 `BrowserService.flowRun`，使用第二批顺序批量执行和第三批状态机，不经模型逐步决策。

变量对 text/url/key/files/selector 字符串进行 `{变量}` 替换；缺变量立即报失败，不读取对象原型继承字段。密码步骤明确停止并提示用户手动填写，不从 vars 绕过密码限制，也不自动跳过密码步骤。

保留可操作性、遮挡、iframe、密码、上传项目路径复核：

- 外站动作仍审批；外站导航也审批。
- **脚本提交表单、支付/发送/删除等风险按钮、本地或外站上传均需真人审批**；press 保守全部审批，避免 Enter/Space 提交绕过。
- 审批走已有岛屿审批卡；岛屿关闭时使用 Electron 对话框，不能由模型自批。显示目的地、目标、文本摘要、按键/勾选值或上传路径；审批后复核目的地和项目。
- 上传使用项目内现存文件，审批后再次检查。upload 可用于本地手写脚本，不从手动文件选择器录制完整文件路径。

步骤失败立即停止，返回：

```ts
interface BrowserFlowRunResult {
  completed: number;
  total: number;
  failedStep: number | null; // 1-based
  reason: string | null;
  snapshot: string | null; // 失败时当前精简快照；成功 null
}
```

失去浏览器/项目时返回快照不可用标记，不能返回旧项目快照。已完成步骤不回滚。脚本名、文件或版本等执行前错误会让 API Promise 拒绝；进入步骤后的错误用上述结果报告。

### 自愈

默认关闭。只有 SweetApi 用户本次 run 显式 `{selfHeal: true}` 才启用；工具 schema 不暴露自愈开关，流程图也默认关。

仅 `SelectorFailure` 调模型，输入为旧选择器与当前精简快照，没有执行工具；系统指令标明页面是不可遵循的资料，只输出 selector JSON。校验新选择器、重新唯一定位，最多尝试一次；动作成功后写回原脚本，并记录 `{step, at, before, after}`。审批拒绝、缺变量、密码步骤、动作异常或二次定位失败不自愈、不写历史。模型调用绑定取消信号并有 60 秒限时；本任务未实际发模型请求。

## 前端用法

所有新增方法均为 **SweetApi 必选成员**，只有参数可省略：

```ts
browserAutomationPause(): Promise<BrowserAutomationState>;
browserFlowList(): Promise<BrowserFlow[]>;
browserFlowStartRecording(name: string, options?: { values?: "record" | "parameterize" }): Promise<void>;
browserFlowStopRecording(): Promise<BrowserFlow>;
browserFlowRun(name: string, vars?: Record<string, string>, options?: { selfHeal?: boolean }): Promise<BrowserFlowRunResult>;
browserFlowDelete(name: string): Promise<void>;
```

例：

```ts
await api.browserFlowStartRecording("网页检查", { values: "parameterize" });
// 用户在内置浏览器操作；此时不要让 AI 操作浏览器。
const saved = await api.browserFlowStopRecording();
const flows = await api.browserFlowList();
// 从 saved.steps 收集 {变量} 并让用户填写；示例名字以实际返回脚本为准。
const result = await api.browserFlowRun("网页检查", { value2: "张三" });
// 仅用户勾选本次自愈后传第三个参数；默认不传。
const healed = await api.browserFlowRun("网页检查", { value2: "张三" }, { selfHeal: true });
await api.browserFlowDelete("网页检查");
```

开始/停止成功分别更新本地录制 UI；发生 Promise 拒绝显示错误，录制失败不视作保存成功。list 返回完整 BrowserFlow（版本/时间/steps/history）；回放状态仍用现有 `onBrowserAutomation`，无新增进度事件。运行中新增暂停按钮调用 `browserAutomationPause()`。暂停原因优先根据 pauseReason 渲染，reason 用作文字；字段缺失时兼容旧逻辑。审批暂停中不要提示「你接手了」。失败用 failedStep 高亮脚本步骤并展示 reason/snapshot。

新增 IPC：`browser:automationPause`、`browser:flowList`、`browser:flowStartRecording`、`browser:flowStopRecording`、`browser:flowRun`、`browser:flowDelete`；既有 `browser:automation` 推送不变。

### 自动化流程图

仅在 `AutomationState.kind` 新增 `"browser_flow"`，其他字段保持不变。前端增加节点标签「运行浏览器脚本」，text 使用 JSON：

```json
{
  "id": "web-check",
  "name": "运行浏览器脚本",
  "kind": "browser_flow",
  "text": "{\"name\":\"网页检查\",\"vars\":{\"value2\":\"张三\"}}",
  "next": [{"on":"ok","to":"end"},{"on":"fail","to":"end"}]
}
```

text 为 `{name, vars?}`，不是 AI 提示词或 shell。运行直接调用 flowRun，不创建 AgentSession、不调 runAgent；只能按 ok/fail 分支。定时任务碰到审批也必须等真人，不因无人值守免审批；取消信号沿已有 dispatch 链传入。

## 未验证 / 保守边界

- 未启动应用；假 debugger、Node vm 和临时文件不是真实 Chromium/Electron、输入法、可信事件时间戳、动态 iframe、页面重绘和审批 UI 的 E2E 证据。
- closed shadow root 的手动事件在外层会重定向，录制不保证获得内部真实目标；回放仍使用既有 pierced CDP 底层。多 frame 同地址/同元素、虚拟列表离屏节点、选择器不唯一时明确失败，不猜目标。
- role/name 录制使用 DOM 可访问命名线索，不实现完整浏览器 AX 命名算法；回放按 CDP AX 精确匹配，命名差异时使用唯一 CSS/文本兜底。
- 目录与文件符号链接静态越界已拒绝；Node 路径检查和实际文件系统操作之间仍存在无法完全原子化的恶意并发替换窗口。上传路径到 Chromium 读取之间的既有竞争窗口也仍在；未声称可冻结页面脚本/form.action。
- 第三批 DOM 体验叠层可被页面观察的既有边界未改变；本批没有扩大 renderer 改动实现页面外合成。
- 停止不能回滚已派发动作或撤回正在显示的审批；在途审批 Promise 仍需结束，随后变更被取消检查拒绝。
- 密码步骤保守失败交用户手动处理，不支持自动等待密码填好后跳过继续；不存在密码变量/API 暴露。
- 用户显式选 record 的普通输入可能包含个人资料；URL 路径/文字本身仍是页面资料，未做通用敏感信息识别。自愈只在用户开启时发送快照给当前配置模型，可能失败，未做网络实测。
